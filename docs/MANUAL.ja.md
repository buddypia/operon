# Operon ユーザーマニュアル

Operon は、AI コーディングエージェント（Claude Code、Codex CLI、Antigravity CLI、
または任意のコマンド）を実行・監督するための、ローカルファーストな macOS アプリです。
各エージェントは独立した `tmux` セッションで動くため、アプリを終了しても作業は続きます。

このマニュアルは日常の使い方をまとめたものです。機能の概要は
[README.ja.md](../README.ja.md)、開発への参加方法は
[CONTRIBUTING.ja.md](../CONTRIBUTING.ja.md) を参照してください。

> **画面上の名称について。** 画面の表示言語は 日本語・English・한국어 から選べます。
> このマニュアルの **太字** は、日本語表示で実際に見えるラベルです。

## 1. インストール

### 必要なもの

| 必要なもの | 備考 |
| --- | --- |
| macOS 12 以降 | Apple Silicon / Intel（パッケージ化した bundle の最小バージョンは 12.0） |
| Rust ツールチェーン | ソースからビルドする場合のみ。[rustup](https://rustup.rs/) で導入 |
| `tmux` | セッションの実行に必須。`brew install tmux` |
| エージェント CLI を 1 つ以上 | `claude`・`codex`・`agy`（Antigravity）が `PATH` 上にあること。任意のコマンドでも可 |
| `gh`（任意） | **PR** タブで、オープン中の PR を一覧できるようになります |

### ソースからビルドして起動

```sh
git clone https://github.com/buddypia/operon.git
cd operon
cargo run --release
```

インストール済みの Operon がある場合は終了してから実行してください（逆も同様です）。
詳しくは[多重起動ロック](#10-トラブルシューティング)を参照してください。

### macOS アプリとしてパッケージ化

```sh
bash scripts/package-macos.sh
```

スクリプトは最初に `cargo fmt --check`・`cargo test --locked`・
`cargo clippy --locked -- -D warnings` を実行し、続いて依存関係を固定した状態で
ビルドして `dist/Operon.app` を作ります。`/Applications` には触れないため、
必要なら bundle を自分でコピーしてください。

この bundle は **ad-hoc 署名** です。ビルドした Mac では動きますが、Developer ID での
署名も公証（notarization）もされていません。別の Mac では Gatekeeper に最初は
拒否されます。*右クリック →「開く」*、または *システム設定 → プライバシーとセキュリティ →
「このまま開く」* で開いてください。他の人に正式に配布するには、Apple Developer ID
証明書と公証が必要です。

### 初回起動

プロジェクトが 1 つもないとき、**プロジェクト**ページには
**まずはプロジェクトを開いてください** と、**最初のセッションを始める前に** のチェックリスト
（`tmux` と、コーディングエージェントの 2 行）が表示されます。どちらかが不足していれば
**セットアップ手順を開く** で **設定 → エージェント** に移動できます。そこでは各ツールの
状態（見出しに `n/6 使用可能`）、**ツールを再確認** ボタン、各 CLI の導入手順を開く
**手順** ボタンが使えます。

Finder から起動したアプリは `PATH` が短くなりますが、Operon は自身のために
`/opt/homebrew/bin`・`/usr/local/bin`・`~/.local/bin`・`~/.cargo/bin` を `PATH` に足すので、
そこにあるツールは見つかります。

## 2. 基本概念

- **プロジェクト** — 手元の任意のフォルダ。Git のチェックアウトであれば Git 機能も使えます。
  エージェントの起動とファイル閲覧はどのフォルダでも使えます。プロジェクトの追加でフォルダが
  変更されることはなく、削除で消えるのは Operon の記録だけです（ファイル・branch・worktree は残ります）。
- **セッション** — 1 つのエージェントが 1 つの `tmux` セッションで動いている状態。
  名前は `operon-` に 8 文字を続けたものです。セッションはプロジェクトに属し、worktree で動かすこともできます。
- **worktree** — 同じリポジトリを別の branch でもう 1 つチェックアウトしたもの。複数のセッションが
  互いのファイルに触れずに並行して作業できます。
- **エージェント** — セッションが実行するツール。**Claude Code**・**Codex CLI**・
  **Antigravity CLI (agy)**・任意のコマンド。（内部の保存値は旧来の `gemini` ですが、
  画面と文書では Antigravity と呼びます。）

画面はツールバーと 4 つのページでできています。

- **ホーム**（⌘1）— いま動いているもの、あなたを待っているもの、最近のセッション、プロジェクトごとの開始ボタン。
- **プロジェクト**（⌘2）— プロジェクト一覧。開くと **概要**・**変更**・**worktree**・**PR**・**ファイル**・
  **エージェント設定** のタブが並びます。
- **セッション**（⌘3）— 左にセッション一覧、右に選んだセッションのターミナル。
- **設定**（⌘,）。

ツールバーには **新しいセッション**（⌘N）、**検索・操作**（⌘K）、設定ボタンがあり、
利用できる場合は Claude の使用量も表示されます。

## 3. エージェントセッションの起動と管理

### プロジェクトを追加する

**プロジェクト**ページで **プロジェクトフォルダを選択…**（⌘O）を押すか、Finder からフォルダを
ウィンドウへドラッグします。**ワークスペースをスキャン…** は、選んだフォルダの 3 階層下までにある
Git リポジトリをまとめて取り込みます。**パスを手入力** からは絶対パスを入力して追加できます。

### セッションを起動する

どのページからでも **新しいセッション**（⌘N）を押します。いまのページの上にシートが開きます。

1. **エージェント** — Codex・Claude Code・Antigravity、または **別のコマンドを使う**。
   緑の印はこの Mac で使えることを表します。任意コマンドの場合は **起動コマンド（必須）** を入力します。
2. **アカウント** — Claude Code と Codex のみ、かつアカウントを登録済みの場合に表示されます
   （[設定](#8-設定と表示言語)を参照）。既定は **このマシン** です。
3. **依頼（任意）** — エージェントにやってほしいこと。最初のメッセージとして入力されます。
4. **作業場所** — **プロジェクト直下**、または worktree（**ワークツリー: ブランチ名** と表示）。
   worktree はプロジェクトの **worktree** タブで作ります。
5. **詳しい設定（任意）** — 初期状態では折りたたまれています。セッション名、モデル、CLI 自身の
   権限モード、**推論の深さ**、その CLI が受け付けるスイッチ、**ほかのセッションの後に開始** が入っています。

**〈エージェント名〉 を起動  ⌘↩** で起動します。**ターミナルだけ開く** はエージェントなしの素の
`tmux` シェルを開きます。**Esc** または ✕ で、起動せずにシートを閉じます。

シートが守っているルール:

- モード・推論の深さ・スイッチはすべてその CLI 自身の一覧から選びます。Operon が独自のフラグを
  作ることはありません。CLI が同時指定を拒否する 2 つのスイッチは、同時にオンにできません。
- 確認なしでファイルを変更できるスイッチやモードには **危険** の印が付きます。
  **理解したうえで起動する** にチェックを入れるまで起動ボタンは無効のままです。
  この確認は、そのようなフラグを含む任意コマンドにも適用されます。
- `tmux` やエージェントが無い場合はその旨が表示され、**設定 → エージェント** への近道が出ます。
- 最後に使ったモデル・モード・推論の深さ・スイッチ・任意コマンドは、エージェントごとに
  `recent-agent-settings.json` に記憶されます。

### セッションを順番待ちにする

**詳しい設定（任意）** の **ほかのセッションの後に開始** を選ぶと、先行セッションの完了を待ってから開始します。
待機中のセッションには **今すぐ開始** が出て、すぐ実行できます。前提のセッションが失敗した場合、
待機中のセッションはブロック状態になり、自動では開始されません。

### 停止・再試行・再開・閉じる

セッション行の隅とターミナルのヘッダーにあるボタンは、状態に合う操作を 1 つだけ表示します。

| 状態 | ボタン |
| --- | --- |
| 実行中 | **停止**（記録は残ります）。停止の完了待ちの間は **停止中…** と表示され、もう一度押すと停止を再試行します |
| 順番待ち | **今すぐ開始** |
| 失敗・結果不明で、保存された会話がない | **再試行** — 古いターミナルを安全に確認して片付けたうえで、もう一度実行します |
| 失敗・結果不明・終了・停止で、保存された会話がある | **会話 ID から再開**。ホバーすると、引き継がれるモデル・モード・スイッチが表示されます |

そのほかの操作:

- **名前を変更**: セッションのタイトルをダブルクリックするか、`···` メニューから。
- **未読にする**: `···` メニューから。
- **セッションを削除** — 行の ✕。動作中のターミナルは先に停止されます。ファイルと worktree は削除されません。
- **ターミナルを閉じる** / **残ったターミナルを閉じる** — 終了・失敗したセッションに残ったターミナルを片付けます。
- ターミナルヘッダーの `···` メニューには、**Terminal.app で開く（マウス操作・tmux 操作用）**、
  **表示中のログをすべてコピー**（色コードなしでバッファ全体をコピー）、**今すぐ同期** があります。

### ターミナルペイン

ペインをクリックするとエージェントに入力できます。日本語 IME など入力メソッドにも対応しています。
アプリ内のスクロールバックは最大 5,000 行です（`tmux` 自体は 50,000 行を保持）。**最新へ** で最新行に戻ります。
サイドパネル（矢印で畳み、**サイドパネルを表示** で再表示）には **ファイル**・**会話**
（これまでに送った依頼）・**変更** の 3 つのタブがあります。

ターミナル出力中のパスはリンクになります。**⌥** を押しながらクリックすると内蔵エディタでその行を開き、
**⌘** を押しながらクリックすると外部アプリで開きます。開けるのは、そのセッションのフォルダ内で
実在するファイルに解決できるパスだけです。dev server が出力するアドレスも同じ方法でブラウザで開きます。
通常のクリックはペインにフォーカスするだけなので、エージェントとの入力が奪われることはありません。

## 4. 状態の監視と通知

### 状態

すべてのセッションは次の 4 つのうちどれかで表示され、ホバーすると詳細が出ます。

| ラベル | 意味 |
| --- | --- |
| **要対応** | 回答待ち、または前提が失敗して止まっている |
| **実行中** | 起動中・作業中・停止処理中・順番待ち |
| **待機中** | 起動していて、次の依頼を待っている |
| **終了** | ターミナルが終わっている（正常終了・失敗・停止・結果不明） |

セッション一覧の見出しには、**要対応**・**実行中**・**待機中**・**終了** の 4 つのトグルがあり、
それぞれ件数が表示されます。オンにした状態のセッションだけに絞り込めます。非表示にしている件数が
表示され、**フィルタを解除** で解除できます。絞り込みは再起動後には引き継がれません。

**ホーム**のバナーは、あなたを待っているセッション（回答待ち・ブロック中・未読の完了）を数え、
その絞り込み済みの一覧を開きます。別のセッションを見ている間にターンが完了すると、そのセッションを開くまで
印が付きます。**未読にする** でもう一度印を付けられます。これらの印は再起動後には残りません。

### 状態の取得元

- **フック（推奨）。** **設定 → エージェント** の **エージェント CLI のフックで状態を検知する** をオンにすると、
  各 CLI 自身の設定ファイル — `~/.claude/settings.json`、`~/.codex/hooks.json`（信頼エントリは
  `~/.codex/config.toml`）、Antigravity は `~/.gemini/config/hooks.json` — と、登録したアカウントの
  フォルダに、Operon 用の小さな項目が追加されます。これで CLI 自身が作業中・待機・完了を報告します。
  既存の項目は保持され、オフにすると Operon が追加した分だけが取り除かれます。各ツールの行には
  **フック 導入済み** / **フック 未導入** / **フック 失敗** が表示され、ホバーで理由が分かります。
- **画面の読み取り。** フックがない場合や、フックの報告が 30 分より古い場合は、ターミナル下部の数行を読んで、
  作業中のエージェントと質問で止まっているエージェントを見分けます。

同じセクションの **初回起動時のフォルダ信頼プロンプトを自動承認する** は、CLI の「このフォルダを信頼しますか」
という質問にだけ答えます。ほかのものは承認しません。

### 通知

**設定 → 通知 → ターンの完了・入力待ち・終了を通知する** をオンにすると、エージェントがターンを終えたとき、
入力待ちで止まったとき、終了したときに macOS の通知が出ます。初めてオンにしたときに macOS が許可を求めます。

### そのほかの表示

- セッションのヘッダーには、そのセッションの worktree が待ち受けているポートが `:5173 vite` のように出ます。
  クリックで開き、右クリックで URL をコピーします。ポートは 30 秒ごとに `lsof` で読み取ります。
- ツールバーには Claude の使用量の枠をどれだけ使ったかが表示されます。Operon が独自にリクエストを送ることはなく、
  Claude Code がすでに報告している値を読むだけです。80% を超えると琥珀色になり、30 分以上更新がないと
  経過時間とともに薄く表示されます。

## 5. Git・diff・ファイル・エディタ

プロジェクトを開いて、そのタブを使います。

### 変更

**変更** タブには **Changes**・**Diff**・**History** の 3 つのビューがあります。

- **Changes** は変更されたファイルの一覧です。次の commit に含めるファイルにチェックを入れます。
  追跡中のファイルの変更は最初からチェック済み、未追跡ファイルは未チェックで始まります。メッセージを書くか、
  **AI に書かせる** を押します（ローカルのエージェント CLI が staged な patch から下書きを入力欄に書きます。
  勝手に commit されることはありません）。そのあと **N ファイルをコミット** を押します。
  `push` の行は upstream との差を示し、リモートが先に進んでいる場合は push を拒否します。
  Operon に force push はありません。commit は、チェックしたファイルだけを staging し直します。
  `git add -p` による hunk 単位の選択が index に残っている場合は、それを壊さないよう拒否します。
- **Diff** は、ファイルごとに折りたためる形で、両側の行番号付きで描画し、変更された行の中の
  実際に変わった語をマークします。**AIレビュー** はローカルのエージェント CLI に diff のレビューを依頼し
  （45 秒で打ち切り）、**コピー** で結果をコピーできます。
- **History** は最近の commit を表示します。

### diff へのメモ

**Diff** では、変更後に存在する行をクリックして、その下にメモを書けます（**この行について書く**、**保存**）。
メモはディスクに保存され、再起動後も残ります。フッターに件数（未解決・送信済・解決済）が出て、
**セッションにまとめて送る**（すべてのファイルと行を明記した 1 通のメッセージにして、そのプロジェクトで動いている
エージェントへ送ります。エージェントがターンの途中なら拒否されます）、**Markdownをコピー**、
**解決済みを消去**、**すべて消す** が使えます。書いたあとに行が変わったメモは、別の行へ黙って移らず、
**行が変わっています** と表示されます。

### worktree

**worktree** タブでは、新しい branch 名から worktree を作れます。プロジェクトのメインライン
（`origin/HEAD`、なければ `origin/main`・`origin/master`・`main`・`master`）から作られ、どれを使ったかも表示されます。
名前が使われている場合は次の番号（`name-2`、`name-3`…）が使われます。各 worktree には
**この場所で新規セッション** と **削除…** があります。削除できるのは変更がなく使用中でない worktree だけで、
確認のうえで削除され、branch は残ります。

リポジトリに `.operon/setup.sh` がある場合、worktree の作成後に冒頭の数行が表示され、
**このリポジトリのセットアップを実行しますか？** と尋ねられます。**実行する** を押すと専用のセッションで
実行され、様子を見たり止めたりできます。**内容が変わるまで、今後は確認しない** にチェックすると、
その内容のスクリプトに限って承認が記憶されます。1 文字でも変えると、再び確認されます。

### PR

**PR** タブには、オープン中の GitHub の PR が、レビューと CI チェックの要約付きで並びます。
GitHub CLI（`gh`）のインストールとログインが必要です。

### ファイルとエディタ

**ファイル** タブには、折りたためるプロジェクトツリー（変更のあるファイルには Git バッジ付き）、
エディタのタブ、行番号、シンタックスハイライトがあります。**⌘S** で保存します。Markdown は
Markdown として描画されます。128 KiB を超えるファイルは読み取り専用で開き、10 MiB までの画像は
プレビューできます。ツリーは `.git`・`node_modules`・`target`・`.next` を読み飛ばします。

Operon がエージェントの作業を黙って上書きすることはありません。開いたあとにディスク上で変更された
ファイルへの保存は拒否されます。開いているファイルは 2 秒ごとにディスクと比較され、未保存の編集がなければ
自動で再読み込みして知らせます。未保存の編集がある場合は、再読み込みか diff かを選ぶバーが出ます。
**エージェント設定** タブには、プロジェクトのスキルと指示ファイルが一覧されます。

## 6. CLI をまたぐ会話の復元

Claude Code・Codex CLI・Antigravity のどの会話も、3 つのどれにでも復元できます。同じ CLI にもう一度復元すれば、
元の会話に影響を与えずに分岐できます。復元は、各 CLI がすでにローカルに保存している transcript ファイルを読んで行います。
**モデルは動かず、トークンも消費せず**、要約もしません。

**セッションから**: 一覧のセッションの `···` メニューで、他の CLI の **〈エージェント名〉 へ履歴を復元** を選びます。

**過去の会話から**: **セッション**ページで **履歴** を押し、**CLI セッション（過去の会話の検出と復元）** を開き、
プロジェクトを選んで **ローカル CLI セッションを検出** を押します。各カードには会話の ID・branch・最後の依頼が出ます。
そのうえで次のどちらかを行います。

- **元の CLI で再開**
- **復元先** を選び、必要なら **復元メモ（任意）** を書いて、**会話全履歴を復元** を押す

復元中は、元の会話・復元先・経過時間を示すウィンドウが出ます。バックグラウンドへ回すこともできます。
同じ **履歴** ページには **ローカル履歴** もあり、最近の Codex と Claude の transcript を全文検索できます。

### 共有セッションアーカイブ

復元のたびに、元の transcript が `shared-sessions/<id>/source.jsonl` にそのまま保存され、
`manifest.json` と読みやすい `restored-conversation.md` が隣に作られます。フォルダは `0700`、
スナップショットは `0600` で作られるため、読めるのはあなたのアカウントだけです。機密性のある依頼・
ツール出力・ソースコードが含まれることがあります。

## 7. キーボードショートカット

| キー | 操作 | 備考 |
| --- | --- | --- |
| ⌘K | **検索・操作** | 矢印キーで移動、Enter で開く。セッションはタイトル・依頼・エージェント・branch・プロジェクトで、プロジェクトは名前・パスで探せます |
| ⌘N | **新しいセッション** | |
| ⌘1 / ⌘2 / ⌘3 | **ホーム** / **プロジェクト** / **セッション** | ⌘2 はプロジェクト一覧に戻ります |
| ⌘, | **設定** | |
| ⌘O | プロジェクトフォルダを選択 | |
| ⌘F | ターミナル内を検索 | Enter で次、⇧Enter で前、Esc で閉じる。入力した内容はエージェントに届きません |
| ⌘↩ | セッションを起動 | 新しいセッションのシート内 |
| Esc | 新しいセッションのシートを閉じる | |
| ⌘S | 開いているファイルを保存 | **ファイル** タブ内 |
| ⌥ + クリック / ⌘ + クリック | ターミナル出力中のパスや URL を開く | エディタで / 外部アプリで |

ショートカットを変えるには、**設定 → キー割り当て** で **キー割り当てファイルを開く** を押します。
初回は現在のキーから `keybindings.json` を作成して Finder で表示します。すでにあるファイルを上書きすることはありません。
形式は次のとおりです。

```json
{
  "version": 1,
  "keybindings": {
    "palette.open": "Mod+K",
    "terminal.find": "Mod+Shift+F",
    "page.settings": null
  }
}
```

`Mod` は ⌘ を表し、ほかの修飾キーは `Shift`・`Alt`・`Ctrl` です。`null` はキーなしを意味します。
操作 ID は `palette.open`・`session.new`・`page.home`・`page.projects`・`page.sessions`・`page.settings`・
`project.add`・`terminal.find` です。1 つのキーを 2 つの操作に割り当てたファイルや、未知の操作を含むファイルは
ファイル全体が拒否され、既定のキーで起動して理由が表示されます。

## 8. 設定と表示言語

**設定**（⌘,）には 5 つのセクションがあります。

| セクション | 内容 |
| --- | --- |
| **外観** | **テーマ**（ダーク（既定）・ライト・ハイコントラスト（ダーク）。開いているターミナルにも即時反映）、**ターミナルとコードのフォント**（Sarasa 系の 4 種）、**言語** |
| **エージェント** | ツールの状態、フックのスイッチ、フォルダ信頼の自動承認、**エージェントのアカウント** |
| **通知** | 通知のスイッチ |
| **データと復旧** | データフォルダのパス、**データフォルダを表示**（Finder で開く）、記録が失われた `tmux` セッションを探す **tmux をスキャン** |
| **キー割り当て** | すべてのショートカットと現在のキー |

**言語**: English・日本語・한국어 から選びます。変更は次のフレームで反映され、保存されます。
初回起動時は、システムの言語（`LC_ALL`・`LC_MESSAGES`・`LANG`、続いて macOS の言語リスト）から選ばれ、
判定できなければ日本語になります。表示言語を English や 한국어 にしても、まだ翻訳されていないラベルは日本語のまま表示されます。

**エージェントのアカウント**: アカウントとは、Codex や Claude Code がログイン情報を置くフォルダ
（`CODEX_HOME` / `CLAUDE_CONFIG_DIR`）のことです。エージェントを選び、名前（例: 仕事）を付けて
**フォルダを選んで追加** を押します。以後、セッション起動時の **アカウント** で選べます。
Operon はそのフォルダを CLI に指し示すだけで、中身を読みません。管理フックも同じフォルダに入ります。
Antigravity にアカウントの仕組みはありません。

## 9. データの保存場所とプライバシー

すべてローカルで動きます。Operon にテレメトリ・アカウント・クラウドサービスはありません。
エージェントは別のツールとして動き、プロジェクトの内容を各提供元へ送信することがあります。
起動前に各エージェントの権限・sandbox モードを確認してください。

Operon のデータは `~/Library/Application Support/com.local.operon/` にあります
（**設定 → データと復旧** に正確なパスが表示され、Finder で開けます）。

| 項目 | 用途 |
| --- | --- |
| `store-v2.json` | プロジェクト・セッション・設定（スキーマバージョン付き、アトミックに書き込み） |
| `store-v2.json.pending-cancellations.json` | 進行中の停止の永続的な記録 |
| `recent-agent-settings.json` | 記憶された起動オプション |
| `agent-accounts.json` | 登録したアカウントのフォルダ |
| `keybindings.json` | あなたのショートカット（作成した場合） |
| `diff-comments.json` | diff に書いたメモ |
| `setup-trust.json` | 承認済みの `.operon/setup.sh` のダイジェスト |
| `agent-hooks/` | 管理フックのスクリプト、endpoint ファイル、ローカルの `hook.sock`（`0700`） |
| `shared-sessions/` | 復元アーカイブ（[第 6 章](#6-cli-をまたぐ会話の復元)） |
| `.operon-instance.lock` | 多重起動ロック |

Operon は、会話を探して復元するために、各エージェント自身の transcript フォルダ（`~/.claude/projects`、
`~/.codex` など）も読み取ります（アップロードはしません）。Operon への改名前のビルドは `xirp-copy` フォルダに
データを置いていました。これは初回起動時に取り込まれます。

## 10. トラブルシューティング

**「`tmux` が必要です」** — `brew install tmux` で導入し、**設定 → エージェント** の **ツールを再確認** を押します。

**エージェントが見つからない（「選んだ AI が見つかりません」）** — CLI が `PATH` 上にある必要があります。
Operon は `PATH` に加えて `/opt/homebrew/bin`・`/usr/local/bin`・`~/.local/bin`・`~/.cargo/bin` を探します。
それ以外（たとえば `nvm` 配下）に入れた CLI は、Finder から起動したアプリからは見えないことがあります。
そのコマンドが動くシェルから Operon を起動する（`open -a Operon`、または `cargo run --release`）か、
CLI を `~/.local/bin` にシンボリックリンクしてください。その後 **ツールを再確認** を押します。

**多重起動ロック** — データフォルダを使えるのは 1 つの Operon だけです。2 つ目を起動すると
**Operon は既に開いています** と表示されるので、もう一方を閉じてからやり直してください。インストール済みの
ビルドと `cargo run` のビルドも同様です。**Operon はローカルデータを開けませんでした** と出た場合は、
データフォルダの権限と空き容量を確認してください。

**状態が「実行中」のまま変わらない／「待機中」のまま** — そのCLIのフックが **フック 導入済み** になっているか
確認してください。**フック 失敗** の場合はホバーで理由が分かります。フックがなければ Operon は画面の読み取りに切り替わります。

**セッションが「終了」と表示され、ホバーに「ターミナルが残っておらず、結果を確認できません」と出る** —
`tmux` セッションが Operon の外で消えたため、結果を確認できません（Operon は「失敗」ではなく
「結果不明」として記録します）。**再試行** か **会話 ID から再開** を使ってください。

**`tmux` にはあるのに Operon にはないセッション** — **設定 → データと復旧 → tmux をスキャン** で一覧され、
**セッションを引き継ぐ** で登録済みのプロジェクトに結び付けられます。

**実際のターミナルから接続する** — セッションは既定の `tmux` サーバー上にあります。
`tmux ls` のあと `tmux attach -t operon-xxxxxxxx` で接続できます。

**keybindings ファイルが無視される** — 通知が問題（不正な JSON・未知の操作・キーの重複）を示します。
修正するか、ファイルを削除して既定に戻してください。

## 11. アンインストールとデータの削除

1. **まずフックのスイッチをオフにします**（**設定 → エージェント**）。各 CLI の設定ファイルから、
   Operon が追加した項目が取り除かれます。登録したアカウントのフォルダの項目も消したい場合は、
   アカウントも削除してください。
2. セッションを停止してから、Operon を終了します。セッションは素の `tmux` セッションなので、
   動いたままのものは止めるまで動き続けます（`tmux kill-session -t operon-xxxxxxxx`）。
3. アプリを削除します。`Operon.app`（`/Applications` やこのリポジトリの `dist/` など）をゴミ箱に移します。
4. Operon のデータを削除するには、`~/Library/Application Support/com.local.operon/` をゴミ箱に移します。
   プロジェクト一覧・セッションの記録・メモ・復元アーカイブが消えます。Claude Code・Codex・Antigravity が
   書いた transcript はそれぞれのツールのものなので、触れられません。

Operon の中でプロジェクトを削除したりセッションを削除したりしても、ファイル・branch・worktree は削除されません。
