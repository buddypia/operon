# Intent: the standing instructions overspend their budget and leave half the skills unnamed

- **Status**: approved
- **Opened**: 2026-10-18

## Problem

Google Research's Harness² (`~/dev/oss/harness2`, Apache-2.0) found by
experiment how the text an agent carries on every turn should be written. Its
validator rejects a harness before any run when, among other things, the
always-on text is over its framework's cap — 8,000 characters for Codex, whose
only always-on file is `AGENTS.md` (every token of it competes with the agent's
own output budget, and a run that reasons until the budget is gone produces
nothing); when a skill is never named in that always-on text by a line saying
when to open it (an unnamed skill is never opened, so it is dead weight); or
when a hooks file has a shape the framework does not dispatch (a malformed one
never fires rather than erroring). Its prompt adds the order in which new
knowledge should be placed — skill, script, subagent, hook, and the always-on
file last, paid for by a cut — and that a rule prose failed to hold belongs in
a hook, not in more prose.

Here `AGENTS.md` alone is 2,846 characters, inside the cap as Harness² states
it. But Claude Code's always-on file is `CLAUDE.md`, which imports `AGENTS.md`,
and that load is 9,133 characters; this change applies the same budget to it
by analogy, because it is what Claude Code pays on every turn. Of the six
skills, three are never named in the file every agent CLI loads, so Codex and
Antigravity are never told when to open the pipeline skill, the root-cause
skill, or the durability skill. Several rules are written twice, once in each
of the two always-on files. And the hook registrations of the three CLIs are
checked for which scripts they run, but not for whether the CLI would read them
at all: the vendored adapter records that an earlier Antigravity registration
wrapped `Stop` the way only tool events are wrapped, which "likely" left the
whole file ignored, and nothing here would have said so.

## Who feels it, and when

Every session, on every turn: the always-on text is paid for before a line of
code is read. A Codex or Antigravity session fixing a bug, or touching the
store, that is never pointed at the skill written for exactly that. And whoever
next edits a hooks file and breaks its shape, which no check reports.

## Desired outcome

The text every turn loads, under each of the three CLIs, fits the budget
Harness² set for Codex, with room left, and
a change that pushes it over is refused before it merges, saying what to move
out and where. Every skill is named, by when to read it, in the one file all
three CLIs load. Each hooks file has the shape its CLI dispatches, and a broken
shape fails the suite instead of switching the guards off in silence. The order
for placing new knowledge is written where every CLI reads it.

The person's request, 2026-10-18: 「~/dev/oss/harness2 이 프로젝트는 Google이
만든 프로젝트야. 이 프로젝트에 알맞게 최대한 적용시켜줘.」 with the rules to take:
AGENTS.md は 8,000 文字以下; 知識を足す優先順位は Skill → Python Script →
Subagent → Hook/Plugin → AGENTS.md（最終手段）; Skill を作ったら必ず AGENTS.md
に When <条件>, read .agents/skills/<name>/SKILL.md のトリガー行を 1 行; AI が
注意書きを無視するならプロンプトを太らせず hooks（PostToolUse）で機械的に
ブロックする.

## Constraints this change inherits

- Lessons already pinned by tests stay pinned: the landing line, the rule for
  when to ask a person, the rule for writing to a person, the three gates, the
  module map, the one entry skill, and the pointer table for path-scoped rules
  (eval 006 measured that a new file needs it).
- Files owned by the vendored worktree bundle (`.claude/.bundle-receipt.json`)
  are regenerated from outside this repository; this change does not edit them.
- Lesson 060: what a CLI does is measured, not assumed.

## Systems likely affected

`src/tests.rs`, `CLAUDE.md`, `AGENTS.md`, the feature-pilot build reference,
`docs/sdlc/bands.yaml`, `docs/sdlc/README.md`.

## Open questions

None. Whether Codex, Antigravity, and Claude Code open a skill the always-on
text does not name is measured in this change's fixtures and recorded in
`plan.md`, not taken from Harness² alone.

## Not in scope

- A new PostToolUse hook. Harness² enforces these three rules in its validator,
  before a harness runs — the equivalent here is the suite in CI — and keeps
  hooks for recurring failures inside the tool loop. Antigravity's PostToolUse
  carries no message back, and the Codex and Antigravity hook files are
  generated by the vendored bundle. No trajectory here shows a prose rule being
  ignored that no guard already refuses. Codex's PostToolUse does carry a
  message back; that alone does not make a hook the right form.
- Template-brace and helper-location rules: they guard Harness²'s own renderer
  and editable surface, which this repository does not have.
- Deleting the vendored `create-pr` skill or the flat catalogue stub
  (change 114 left the stub to the bundle).
