# Spec: Event-driven, damage-tracked terminal TUI pipeline for session panes

- **Intent**: `./intent.md`
- **Status**: approved

## Requirements

1. **Event-driven tmux output stream with frame-budget coalescing and respawn cooldown**: For each active session currently visible on screen (at most `PANE_MAX` = 4), Operon maintains a passive, size-ignoring `tmux` control-mode watcher (`tmux -C attach-session -t <name> -fignore-size`, never writing to `stdin` until detach so `tmux send-keys` is not blocked by `CLIENT_READONLY`, and using single-token `-fignore-size` so `no_source_file_can_force_a_push` never sees a standalone `"-f"` literal) built via `tmux_command()` after `is_safe_tmux_name` validation and spawned through `spawn_piped_streaming` in `src/exec.rs`. PTY output notifications (`%output`, `%extended-output`, `%layout-change`) coalesce within `TERMINAL_STREAM_FRAME_BUDGET` (`16ms` when focused, `250ms` when unfocused) into a single `tmux_capture_with_cursor` call. Only while a session's watcher worker thread is live (`is_watching(session_id) == true`), blind `33ms` echo polling (`poll_terminal_echo`), post-`send-keys` speculative `request_session_output`, and duplicate `on_screen` captures in `request_session_poll` are suppressed; if a watcher exits or fails to attach (e.g. an exited pane or an in-memory unit test), `is_watching` immediately flips to `false` so fallback polling remains intact, and `TerminalStreamManager` enforces a respawn cooldown of `SESSION_POLL_INTERVAL` (`2s`) for that `(session_id, tmux_name)` so `update()` never fork-storms `tmux -C`. Detaching a pane from view, transitioning session status away from `Active`, or exiting Operon closes the watcher's `stdin` and reaps the child process immediately.
2. **Zero repaint and zero layout work on unchanged snapshots**: When a captured terminal snapshot's `(theme, output_fingerprint, cursor)` matches the last delivered snapshot for that session, the background stream drops it without waking `egui` (`request_repaint()`), without sending redundant UI updates, and without incrementing `terminal_output_generations`. When only `TerminalCursor` changes under the same `AppTheme` and output text, `terminal_cursors` updates and wakes the visible pane without re-parsing ANSI lines or invalidating `TerminalPaneRenderCache` galleys.
3. **Incremental line-level ANSI layout without whole-buffer allocation**: Terminal ANSI layout (`IncrementalTerminalLayout` / `terminal_line_layouts_incremental`) strips `\r` per line without allocating a whole-buffer `output.replace('\r', "")` copy and reuses cached `LayoutJob` entries for every line whose `\r`-cleaned text, incoming `TerminalTextStyle`, and `AppTheme` match the previous snapshot—both for in-place TUI row updates and across scrollback shifts up to `TERMINAL_SCROLLBACK_LINES` (`5000`)—producing `Vec<LayoutJob>` output identical to `terminal_line_layouts`.
4. **Row-level dirty `Galley` reuse in `TerminalPaneRenderCache`**: When a pane's `TerminalPaneKey` misses (because `output_generation` advanced or `visible_rows` scrolled), `TerminalPaneRenderCache` reuses cached `Arc<egui::Galley>` entries for every visible row whose laid-out line identity, font size, theme, and `pixels_per_point` match, invoking `fonts.layout_job` under a single `ctx.fonts` lock only for dirty or newly visible non-empty rows, bounded to `MAX_CACHED_TERMINAL_ROW_GALLEYS` (`2048`) entries and cleared on theme/font/cache reset.
5. **Dirty-line-aware negative path-cache TTL and single pointer query during streaming**: `OperonApp` tracks negative path probe timestamps in `negative_path_probed_at` (bounded to `MAX_CACHED_TERMINAL_ROW_GALLEYS` = `2048` entries and cleared on session switch/removal). When `set_session_output` updates a session's text, a negative (`None`) entry in `resolved_paths` / `terminal_path_caches` is evicted immediately if **(a)** it has no timestamp in `negative_path_probed_at`, **(b)** `TERMINAL_NEGATIVE_PATH_TTL` (`2s`) has elapsed since it was probed, or **(c)** any newly changed/dirty line in the updated output mentions that path; timestamped negative entries within `2s` that appear only on unchanged static lines remain cached so hovering non-file dotted tokens during TUI streaming triggers zero `unresolved_paths` pushes, zero extra `request_repaint()` calls, and zero main-thread `canonicalize()` re-probes, while newly printed dynamic files (`test_set_session_output_evicts_negative_cache_for_dynamic_files`) and un-timestamped entries (`test_set_session_output_skips_redundant_relayout_and_generation_bump_when_unchanged`) evict immediately. In addition, `terminal_rows` reads `hover_pos()` once per pane pass rather than once per visible row, and binary-searches sorted `search.matches` per visible row.
6. **Allocation-lean session workspace frame and module line-budget safety**: `ui_workspace_projects` renders without cloning `self.store.projects` on every frame, `ui_tab_workspace` measures and draws non-truncated tab titles with a single `Galley` layout per tab instead of shaping twice, and terminal input/echo/resize/watcher methods move from `src/app.rs` into `src/app/terminal_output.rs` so `src/app.rs` shrinks below `9979` lines while `src/app/screens.rs` also stays below the `10000`-line `propose` band.

## Behaviour

- **Happy path (active TUI session)**:
  - Typing into Claude Code, Codex, Gemini CLI, `vim`, or shell prompts sends keys via `TerminalInput` and paints the echoed characters as soon as `tmux` emits `%output` via `tmux_capture_with_cursor`, with zero trailing 33ms timer wakeups after the echo lands.
  - Autonomous TUI animations, progress bars, and streaming output update smoothly up to ~60 FPS (`16ms` coalescing when focused; `250ms` when Operon is unfocused in the background) instead of stalling for `2s` between polls.
  - Leaving 1–4 active TUI panes open and idle produces zero `tmux_capture_with_cursor` calls from the stream watcher and zero terminal galley rebuilds.
- **Empty / loading state**:
  - Before the first capture arrives for a newly started session, the pane continues to display `ターミナル出力を待っています…` (`src/app/screens.rs`, existing `tr` string; no new user-facing copy).
- **Alternate-screen TUI state**:
  - Full-screen TUIs (`htop`, `vim`, full-screen Ink/Ratatui views) have `body_rows == pane_rows` in `tmux_capture_with_cursor` (without `-J`), so `terminal_cursor_row` (`src/ui/terminal.rs`) and `TerminalCursor` (`{ x, y, pane_rows }` in `src/models.rs`) continue to work unchanged without touching `src/models.rs`.
- **Interrupted / dead / exited pane state**:
  - When a `tmux` session exits (`%exit` or EOF on the control stream) or does not exist on the server, the watcher marks itself inactive, records a `SESSION_POLL_INTERVAL` (`2s`) respawn cooldown for `(session_id, tmux_name)`, and exits cleanly without raising an error toast; fallback echo polling and `poll_sessions` state transitions (`正常終了`, `停止済み`, auto-restore, or `要対応`) continue unchanged.
  - If `tmux_capture_with_cursor` fails on an explicit `SessionOutput` request, existing Japanese notice `ターミナル出力を読み取れませんでした: {error}` is preserved unchanged.
- **Too-large / flood output state**:
  - If a command floods stdout (e.g. `yes` or a multi-megabyte log dump), the control-mode reader scans raw `stdout` in fixed `8192`-byte stack buffers (never accumulating unbounded `%output` lines in heap strings), coalesces notifications to at most one capture per `16ms` (`60Hz` ceiling), and enforces `COMMAND_OUTPUT_MAX_BYTES` (`8 MiB`) and `Duration::from_secs(5)` via `run_command_with_timeout` in `src/exec.rs`.

## Design

### Classification: EXTEND existing modules (no new top-level `src/*.rs` module)

- **`src/config.rs`**:
  - Add `TERMINAL_STREAM_FRAME_BUDGET: Duration = Duration::from_millis(16)`.
  - Add `TERMINAL_STREAM_UNFOCUSED_BUDGET: Duration = Duration::from_millis(250)`.
  - Add `MAX_CACHED_TERMINAL_ROW_GALLEYS: usize = 2048`.
  - Add `TERMINAL_NEGATIVE_PATH_TTL: Duration = Duration::from_secs(2)`.
- **`src/exec.rs`**:
  - Extend subprocess helpers with `spawn_piped_streaming(command: &mut Command) -> Result<StreamingChild>` that strips `INHERITED_REPOSITORY_POINTERS` (`for pointer in INHERITED_REPOSITORY_POINTERS { command.env_remove(pointer); }`), configures `stdin(Stdio::piped())`, `stdout(Stdio::piped())`, and `stderr(Stdio::null())`, and spawns `Child` with zero `unsafe`.
  - `StreamingChild` provides `take_stdout()`, `shutdown()` (drops `stdin` first so `tmux -C` detaches cleanly in ~2ms, polls `child.try_wait()` up to `25ms`, and falls back to safe `child.kill()` + `child.wait()` so no child or zombie can leak), and `Drop` calling `shutdown()`.
- **`src/tmux.rs`**:
  - Keep existing single-process `tmux_capture_with_cursor` and `parse_tmux_capture_with_cursor` / `parse_tmux_cursor_line` intact.
  - Add `tmux_spawn_output_watcher(name: &str) -> Result<StreamingChild>` (backed by pure `tmux_output_watcher_args(name)`) checking `is_safe_tmux_name(name)` and invoking `tmux_command()` (`-L operon_suite` under `#[cfg(test)]`) with `["-C", "attach-session", "-t", name, "-fignore-size"]` through `spawn_piped_streaming` in `src/exec.rs`.
  - Add pure helper `tmux_control_chunk_has_activity(carry: &mut ControlLineState, chunk: &[u8]) -> ControlChunkSignal` (`Activity`, `Exited`, `None`) so the stream parser operates in bounded `O(1)` memory over arbitrary chunk boundaries and is unit- and model-testable without spawning processes.
- **`src/ui/terminal.rs`**:
  - Introduce `CachedTerminalLine` (carrying `line_id: u64`, `style_in: TerminalTextStyle`, `style_out: TerminalTextStyle`, `raw_hash: u64`, `raw: Box<str>`, and `job: LayoutJob`) and `IncrementalTerminalLayout` (`theme: AppTheme`, `lines: Vec<CachedTerminalLine>`).
  - Implement `terminal_line_layouts_incremental(output: &str, theme: AppTheme, previous: Option<&IncrementalTerminalLayout>) -> (IncrementalTerminalLayout, Vec<LayoutJob>, Vec<u64>)` (plus dirty line indices or parsed-line count for dirty-line path eviction and tests):
    - Iterates `output.split('\n')`, stripping `\r` with `Cow::Borrowed` when no `\r` is present (zero full-buffer allocation).
    - Detects scrollback shift `shift` (`0..=64`) when lines scroll off the top at `TERMINAL_SCROLLBACK_LINES`, then checks candidate indices (`idx` and `idx.saturating_add(shift)`) in `previous` (when `previous.theme == theme`) for exact `style_in == style && raw_hash == hash && entry.raw.as_ref() == clean_line`.
    - Reuses `entry.line_id` and `entry.job` on hit, advancing `style = entry.style_out` in `O(1)`; parses ANSI and assigns a fresh monotonic `line_id` only on dirty/new lines.
  - Extend `TerminalPaneRenderCache` with a bounded row-level galley map (`row_galleys: HashMap<TerminalRowGalleyKey, Arc<egui::Galley>>`, capacity `MAX_CACHED_TERMINAL_ROW_GALLEYS` with clear/eviction on overflow and in `clear()`, plus `#[cfg(test)] row_galley_builds()` / `row_galley_hits()`) keyed by `(line_id_or_job_hash, font_bits, theme, pixels_per_point_bits)`.
  - Update `TerminalPaneContext` to pass optional `line_ids: Option<&[u64]>` alongside `lines: &[LayoutJob]`. When `TerminalPaneKey` misses, `get_or_render_rows` locks `ctx.fonts` at most once to shape only non-empty rows missing from `row_galleys`.
  - In `terminal_rows`, query `ui.input(|i| i.pointer.hover_pos())` once before the visible-row loop, binary-search `search.matches` via `partition_point`, and pass `pointer` into `terminal_row_links` only when `pointer` lies within the row's vertical band.
- **`src/app/terminal_output.rs` & `src/app.rs`**:
  - Move `poll_terminal_echo`, `terminal_echo_poll_wait`, `flush_terminal_input`, `is_layout_dragging`, `finish_layout_drag`, `request_terminal_resize`, and `flush_terminal_resize` from `src/app.rs` into `src/app/terminal_output.rs` to keep terminal runtime logic cohesive and shrink `src/app.rs` well below `9979` lines.
  - Add `TerminalStreamManager` in `src/app/terminal_output.rs`:
    - Reconciled each frame in `update()` (`sync_terminal_streams(focused)`) against active sessions in `terminals_on_screen()` (max `PANE_MAX = 4`) when `self.tools.tmux` is true, honoring a `SESSION_POLL_INTERVAL` (`2s`) respawn cooldown after worker exit/failure; shut down cleanly in `on_exit` and `Drop`.
    - Each per-pane worker owns its `StreamingChild` and `live: Arc<AtomicBool>`, shares `focused: Arc<AtomicBool>` and `theme: Arc<AtomicU8>`, coalesces `%output` / `%extended-output` / `%layout-change` bursts using pure `stream_coalesce_delay(last_capture_at, now, budget)` (`Duration::ZERO` when `now - last_capture_at >= budget`, else `budget - elapsed`), runs `tmux_capture_with_cursor`, skips unchanged `(theme, fingerprint, cursor)` with **zero** `request_repaint()`, skips ANSI layout on cursor-only deltas under the same `theme` while delivering the updated cursor, and runs `terminal_line_layouts_incremental` on text/theme deltas before sending `StreamedTerminalFrame` and calling `repaint.request_repaint()` if still visible.
  - Clear `terminal_incremental_layouts` and `terminal_line_ids` on theme switch in `apply_appearance` (alongside `terminal_output_fingerprints.clear()`) and remove per-session entries in `remove_session_record`.
  - Add bounded `negative_path_probed_at: HashMap<String, Instant>` (cap `MAX_CACHED_TERMINAL_ROW_GALLEYS`, cleared on session switch and `remove_session_record`) populated by `resolve_terminal_paths` when caching `None`, and update `set_session_output` to evict a `None` entry immediately when un-timestamped, expired (`>= TERMINAL_NEGATIVE_PATH_TTL`), or mentioned on any dirty line of the new output.
- **`src/app/screens.rs`**:
  - In `ui_workspace_projects`, iterate project indices/IDs instead of `self.store.projects.clone()` on every frame; clone only the single `Project` if a mutation action triggers.
  - In `ui_tab_workspace`, reuse the measured `Arc<egui::Galley>` when a tab title fits within `max_text_w` instead of shaping the title a second time through `egui::Label`, keeping `src/app/screens.rs` below `10000` lines.

## Flagged concerns

- **Could a `tmux -C` watcher alter the target session's window dimensions, block `send-keys`, leak an attached client after tab switch/app exit, or fork-storm on a missing session?** — Resolved empirically on `tmux 3.8` and by design: `-fignore-size` (without `read-only`, which makes `tmux 3.8` reject `send-keys` with `client is read-only` when no interactive client is attached) preserves the session's `#{window_width}x#{window_height}` on attach and across `resize-window` while keeping `stdin` completely unwritten until detach; closing child `stdin` detaches `tmux -C` with exit `0` in ~2.3ms (`StreamingChild::shutdown` falls back to `Child::kill()` + `Child::wait()` after `25ms`), and `TerminalStreamManager` enforces a `2s` respawn cooldown on dead/missing targets while clearing `is_watching` immediately so fallback polling works seamlessly.
- **Could incremental line-level ANSI caching misrender multi-line SGR colour/bold state when an earlier line changes an escape code without changing later lines' raw text?** — Resolved by including `style_in: TerminalTextStyle` and `AppTheme` in the exact hit predicate (`previous.theme == theme && entry.style_in == current_style && entry.raw.as_ref() == clean_line`) and recording `style_out` on each cached line; exhaustively model-checked by `model_check_tui_292_incremental_ansi_and_coalescer_equivalence`.

## Rejected alternatives

- **Embed `alacritty_terminal` or `vt100` crate directly**: Rejected because `Cargo.toml` / `Cargo.lock` is a `paused` high-risk surface, and Operon relies on `tmux` to keep agent sessions alive across app restarts; `tmux` already maintains the authoritative VT grid.
- **Send `capture-pane` commands interactively over `tmux -C` stdin and parse `%begin`/`%end` blocks**: Rejected because raw pane output inside `%begin ... %end` is unescaped and a terminal line printing `%end <ts> <num> 1` could spoof framing; using `tmux -C -fignore-size` with idle `stdin` strictly as a wake signal and capturing via `tmux_capture_with_cursor` gives zero framing ambiguity and zero command-string injection surface.
- **Pass `-J` to `capture-pane` or retain all negative path entries unconditionally for 2s**: Rejected because `-J` joins wrapped rows and breaks `terminal_cursor_row`, while unconditional 2s retention would delay newly created build outputs printed on fresh terminal lines (`test_set_session_output_evicts_negative_cache_for_dynamic_files`); dirty-line-aware eviction preserves instant dynamic-file discovery while keeping static-line hover entries cached.
