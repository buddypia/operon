# Spec: Zero-rerender drag pipeline and derived-state render caching across Operon

- **Intent**: `./intent.md`
- **Status**: approved

## Requirements

1. **Unified drag tracking, deferred tmux resizes, and zero-group-clone tab drop checks (R1)**:
   - `OperonApp` tracks dock border/split divider drags (`dock_resize_drag: bool`) alongside `workspace_divider_drag`, `workspace_drag`, and `dock_drag` in `is_layout_dragging()`, and tracks all active drags including `workspace_column_drag` and `column_drag` in `is_any_drag_active()`.
   - While `is_layout_dragging()` is `true`, `request_terminal_resize` records/updates `terminal_resize_requested` and `terminal_resize_changed_at` without spawning `BackgroundKey::TerminalResize` (`tmux resize-window`), and `flush_terminal_resize` defers flushing until `finish_layout_drag()` runs when the drag ends or cancels (`!any_dock_rule_dragged`, Escape, or pointer loss), sending at most one settled resize per visible session on release while keeping `session_255_terminal_resize_waits_until_the_size_settles` (`TERMINAL_RESIZE_SETTLE`) debounce semantics outside drags.
   - `WorkspaceTabs::can_move_tab(&self, tab, target, drop, area) -> bool` in `src/ui/session_tree.rs` computes drop validity using `self.layout` only (at most `PANE_MAX = 4` leaves) without cloning `Vec<WorkspaceGroup>`, `Vec<WorkspaceTab>`, or `DocumentId` `PathBuf`s, returning the exact same boolean as `let mut preview = self.clone(); preview.move_tab(tab, target, drop, area)` for every state; `ui_tab_workspace` uses `can_move_tab` during drag hover and mutates `self.workspace` only on drop release.
   - While `is_any_drag_active()` is `true`, periodic `SESSION_POLL_INTERVAL` background poll triggers (`request_session_poll`, `request_port_scan`, and `watch_active_document`) in `OperonApp::logic` / `ui_tab_workspace` are suppressed while existing result/stream channel drains continue.

2. **Content-fingerprinted workspace sync, deduplicated stream sync, and `SidebarViewCache` (R2)**:
   - `sync_workspace_live_sessions` computes a zero-allocation `u64` fingerprint over all inputs (`workspace_project`, `selected_session`, project IDs, session IDs / project assignments / statuses / `created_at`, `cancellation_pending`, `session_arrangement`, `workspace`, and `project_workspaces`). When unchanged from `last_workspace_sync_fingerprint`, it returns immediately in `O(1)` (`#[cfg(test)] workspace_sync_hits`); when dirty, it precomputes a rank lookup map (`O(S)`) before sorting/arranging tabs and stores the post-sync fingerprint.
   - `OperonApp` reconciles `self.visible_sessions` via `sync_visible_sessions_and_streams(&mut self, focused: bool)`: it collects visible session IDs into a scratch `Vec<Uuid>` and only acquires `self.visible_sessions.write()` when the visible set changed from `last_visible_sessions`, eliminates unconditional duplicate `visible_sessions` writes and `sync_terminal_streams(focused)` calls at the end of `OperonApp::ui` when `terminals_on_screen()` and focus/theme did not change since `OperonApp::logic`, and short-circuits steady `sync_terminal_streams` calls when all desired `(session_id, tmux_name)` entries are already live in `self.terminal_streams.entries` with zero cooldown expirations (zero `String` cloning).
   - Nested `O(S²)` / `O(S×T)` scans in `status_group_counts`, `status_group_counts_for_chosen_agents`, and `track_attention` are eliminated using per-pass session ID / open-tab lookup structures.
   - `SidebarViewCache` caches computed tile counts, `waiting_for_user`, `total_matching_rows`, sorted projects, folded flags, per-group header counts/first-session IDs, and sorted session rows (`title` + `SessionStatusView`) keyed by a content fingerprint covering store sessions/projects, `session_arrangement`, workspace/project workspaces, filters, `cancellation_pending`, `session_activity`, `hook_status`, first prompt turn text identity, working-time minute bucket, and active UI language. Steady and drag frames reuse `SidebarViewCache` without cloning `self.store.projects`, `self.store.sessions`, or regenerating titles/status strings.

3. **Cached Diff row tables and bounded row `Arc<egui::Galley>` shaping (R3)**:
   - `DiffRenderCache` in `src/ui/diff.rs` caches flattened `DiffRow` vectors (both unified and side-by-side pairs), `change_rows`, `offsets`, and `widest` keyed by `(files_hash, collapsed_hash, annotations_hash, side_by_side, editable, cell_y_bits)`, eliminating per-frame table rebuilds during scroll, steady frames, and resize frames while the layout mode is unchanged.
   - `DiffRenderCache` also caches shaped `Arc<egui::Galley>` objects keyed by `(file_idx, line_idx, side, max_chars)` within a generational `(files_hash, palette_key, ppp_bits, cell_bits)` cache bounded by `MAX_CACHED_DIFF_ROW_GALLEYS` (`4096`) in `src/config.rs`, shaping all visible viewport misses inside at most one `ui.fonts_mut` lock per frame and painting cached `Arc<egui::Galley>` directly on subsequent frames.

4. **Cached syntax themes, Editor/Gutter `Arc<egui::Galley>`, Viewer row `Galley`s, and zero-alloc cursor line tracking (R4)**:
   - `semantic_theme` in `src/ui/syntax.rs` parses the 17 static `ScopeSelectors` strings once via `OnceLock` instead of parsing them on every highlight pass.
   - `CachedEditorTextLayout` retains `syntax_galley: Option<(u32, u32, Arc<egui::Galley>)>` (`(ppp_bits, wrap_width_bits, galley)`) and `gutter_galley: Option<(u32, Arc<egui::Galley>)>` (`(ppp_bits, galley)`). In `ui_editor_text`, unchanged frames return `Arc::clone` for both gutter and `TextEdit::multiline` layouter with zero `LayoutJob::clone()`, zero `line_numbers.clone()`, and zero `fonts_mut` shaping calls.
   - Focused editor cursor line calculation in `ui_editor_text` counts `'\n'` over `chars().take(char_idx)` cached by `(doc_id, last_cursor_char_idx)` without allocating a prefix `String`.
   - `ViewerRowLayout` retains `galley: Option<(u32, Arc<egui::Galley>)>` so `ui_editor_viewer` paints cached `Arc<egui::Galley>` without cloning `LayoutJob` per visible row on repeat frames.

5. **Markdown preview per-block `Arc<egui::Galley>` cache and large-document viewport culling (R5)**:
   - `RenderedBlock` in `src/ui/markdown_view.rs` stores width/DPI-keyed `Arc<egui::Galley>` caches (`Heading`, `Paragraph`, `Quote`, `Bullet` items, `Code` fences, `Table` cells) and `measured_height: Option<(u32, u32, f32)>`, populated under the active `Palette` and `pixels_per_point`. `Code` fence galleys depend only on `ppp_bits` so pane-width drags never re-shape code blocks.
   - When a document has more than `MARKDOWN_VIEWPORT_CULL_THRESHOLD` (`32`) blocks, blocks beyond `300.0` pt outside `ui.clip_rect().y_range()` whose `(width_bits, ppp_bits)` height is already known reserve exact vertical space via `ui.allocate_exact_size` instead of rebuilding or painting off-screen widgets.

6. **Fast `friendly_path`, once-decoded PNG marks, zero-clone file tree rows, cached `⌘K` palette, and module line-budget reduction (R6)**:
   - `friendly_path` in `src/ui/widgets.rs` caches the resolved home directory path string once via `OnceLock<Option<String>>`.
   - `decode_png_mark` / `png_texture` caches decoded bundled `ColorImage` data in a process-wide `OnceLock<Mutex<HashMap<...>>>` while keeping per-`egui::Context` `TextureHandle` isolation intact.
   - `file_tree_rows` in `src/ui/files.rs` replaces per-node `(project, node.path.clone())` lookups with borrowed `&Path` membership over a pre-filtered project set, and `OperonApp` maintains `FileTreeRowCache` keyed by `(project_id, filter, show_hidden, scan_fingerprint, expanded_hash)` so `ui_file_tree` avoids rebuilding row metadata and `to_string_lossy()` strings on every frame.
   - `CachedPaletteView` on `OperonApp` caches `(Vec<PaletteEntry>, usize)` by query, selection, store/scan/document/keymap/language fingerprint and clears on `open_command_palette` / `close_command_palette`, so `handle_palette_keys` and `ui_command_palette` evaluate entries at most once per query change and zero times during arrow-key navigation.
   - Relocating cohesive terminal search handlers and `queue_terminal_input` into `src/app/terminal_output.rs`, and relocating sidebar filter/drag helpers plus workspace/tab navigation & session filter/count/attention helpers (`attention_count`, `status_group_counts`, `status_group_counts_for_chosen_agents`, `track_attention`, `open_next_waiting_session`, `open_waiting_session`, `session_attention_line`, `attention_wait`, `session_matches_*`, `toggle_*_filter`, `clear_*_filter`, `status_view`, `open_session_in_terminal`, `workspace_tab_project`, `switch_workspace_project`, `select_workspace_project`, `set_terminal_session_context`, `select_session`, `mark_session_unread`, `is_session_unread`, `is_session_on_screen`, `terminals_on_screen`, `close_pane`, `activate_workspace_tab`, `close_workspace_tab`, `remember_closed_tab`, `reopen_closed_tab`, `step_workspace_tab`, `note_session_activity_change`) into `src/app/session_order.rs` shrinks both `src/app.rs` and `src/app/screens.rs` below `9500` lines without creating new `.rs` modules or disturbing `CLAUDE.md`, `docs/features/domains.yaml`, or source-pin tests in `src/tests.rs`.

## Behaviour

- **Happy path**: All pages (`Home`, `Sessions`, `Projects`, `Knowledge`, `Settings`) and dialogs (`⌘K` palette, launch sheet, history) render identically to before. Steady UI frames and drag operations (dock border resize, split pane divider resize, dock panel edge docking, tab drag-to-split/reorder, sidebar column project/session drag reorder, diff/editor/viewer/Markdown scrolling, and `⌘K` arrow navigation) hit cached outputs and perform zero redundant parsing, sorting, shaping, or subprocess launches.
- **Empty / loading state**: Empty workspace, empty tree, empty diff (`変更はありません。`), empty search (`一致する項目がありません`), and loading editor state behave identically.
- **Drag cancellation & edge resize**: Pressing Escape or releasing outside a valid target cancels drags and still flushes any pending settled terminal geometry once via `finish_layout_drag()`.
- **Cache invalidation / error / stale-prevention**: Changing theme, UI language, DPI (`pixels_per_point`), pane width/wrap width, fold state, filters, diff content, editor buffer bytes, or direct test mutations to `store.projects`, `store.sessions`, `session_arrangement`, or `workspace` changes the content fingerprint immediately and rebuilds cleanly without ever showing stale data.

## Policy conformance

| Policy | Applies? | How this change satisfies it |
|---|---|---|
| Colour — a new role means three palette rows plus a `DESIGN.md` entry, and WCAG 2.1 AA against every surface | Does not apply | Zero colours, palette tokens, or visual styles change. |
| Icons — a new mark means an `ICON_*` constant in `src/glyphs.rs` and an `ICON_VOCABULARY` entry | Does not apply | Zero icons or glyphs are added or altered. |
| Identifier SSOT — a string two places must agree on lives in `src/config.rs`, and the round trip is what gets tested | Applies | Cache capacities and thresholds (`MAX_CACHED_DIFF_ROW_GALLEYS`, `MARKDOWN_VIEWPORT_CULL_THRESHOLD`) live in `src/config.rs`. |
| Durability — see `.claude/skills/durability-invariants/SKILL.md`; schema change means a `STORE_SCHEMA_VERSION` bump | Does not apply | `src/store.rs`, `src/models.rs`, cancellation sidecars, and `STORE_SCHEMA_VERSION` are completely untouched. |
| Subprocess safety — new children go through `src/exec.rs`; new launch paths through the gates in `src/agents.rs` | Applies | Zero new child spawn sites; deferred terminal resizes continue exclusively through existing `BackgroundKey::TerminalResize` and `src/tmux.rs` -> `src/exec.rs`. |
| Documentation — user-facing docs change in all three languages together | Does not apply | Internal performance & caching optimization with unchanged user-visible UI, commands, and workflows. |
| Local-first — no telemetry, accounts, cloud calls, or new `unsafe` | Applies | Pure in-memory/per-context UI caching; zero network calls, zero new crates, and zero new `unsafe` blocks (`unsafe_blocks` remains unchanged from `main`). |
| Budgets — any new scan or output path states its byte and item ceiling | Applies | `DiffRenderCache::row_galleys` capped at `MAX_CACHED_DIFF_ROW_GALLEYS` (`4096`), `MarkdownPreviewCache` scoped to active document with viewport culling past `MARKDOWN_VIEWPORT_CULL_THRESHOLD` (`32`), `SidebarViewCache` / `FileTreeRowCache` / `CachedPaletteView` hold single active-view snapshots only. |

## Flagged concerns

- **Could cached sidebar rows, workspace syncs, diff rows, editor galleys, Markdown blocks, or palette results ever show stale content when underlying state or direct struct fields change in runtime or tests?** — Resolved by deriving invalidation keys from zero-allocation content fingerprints over the live fields (rather than relying solely on manually called invalidation hooks in setters) and by including `SyntaxColours`, active `Language`, `pixels_per_point` bit representations, and quantized wrap width in every layout cache key, verified exhaustively with `exhaustive_check`.
- **Could deferring `tmux resize-window` during `dock_resize_drag` or `workspace_divider_drag` leave a terminal at an outdated size if a pointer drag ends via Escape or window focus loss?** — Resolved by setting `dock_resize_drag = false` and calling `finish_layout_drag()` whenever `!any_dock_rule_dragged`, when Escape is pressed, or when `workspace_divider_drag` / `workspace_drag` / `dock_drag` ends or cancels, flushing all `terminal_resize_requested` entries at their settled geometry once.
- **Could moving helpers out of `src/app.rs` and `src/app/screens.rs` break `tests.rs` source-pin assertions or `domains.yaml` ownership checks?** — Resolved by relocating `~580+` lines out of `src/app.rs` and `~427` lines out of `src/app/screens.rs` only into existing `src/app/session_order.rs` and `src/app/terminal_output.rs` (zero new `.rs` files), preserving `ui_workspace_projects..toggle_project_fold`, `ui_terminal_session_tabs..ui_terminal_panel`, and `ui_terminal_pane..workspace_tab_title` boundaries and `RichText::new(&project.name)` / `RichText::new(&title)` expressions in `src/app/screens.rs`, and updating feature `spec.md` symbol lists.

## Rejected alternatives

- **Switch Operon away from `egui` to a retained-mode widget framework or custom renderer**: Rejected because it would rewrite the entire frontend, alter visual chrome/UX, violate `Cargo.toml` `paused` constraints, and risk regressions across 900+ tests; caching `Arc<egui::Galley>`, flat layout tables, derived view models, and deferring D&D side effects achieves retained-mode speed inside `egui`.
- **Use dirty boolean flags updated only inside explicit setter methods**: Rejected because several code paths and existing unit tests mutate `store.projects`, `store.sessions`, `session_arrangement`, and `workspace` fields directly without setters; fast content-addressed `u64` fingerprints catch every direct mutation with sub-microsecond overhead and zero stale-cache bugs.
- **Create a brand-new standalone UI cache module for shared caches**: Rejected because adding a new `.rs` module requires editing `src/main.rs` (`paused` surface) as well as `CLAUDE.md` and `docs/features/domains.yaml`; extending existing domain-owned submodules keeps `src/main.rs` untouched and avoids domain/module churn.
