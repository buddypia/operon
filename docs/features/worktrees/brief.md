# worktree とセットアップ

## 何のための機能か

1 つのリポジトリで、複数のエージェントが互いのファイルを壊さずに同時に作業できるよう、
branch ごとの作業フォルダ（worktree）を作ります。作業が終われば main に取り込み、片付けまでを行います。
リポジトリが用意している準備や実行のスクリプトは、中身を見せて許可をもらってからだけ動かします。
エージェントが作業を誤った場合に備えて、途中の状態に戻す「チェックポイント」もあります。

## 誰がいつ使うか

- 同じ課題を別々の方法で複数のエージェントに試させたいとき。
- 1 つの branch の作業を終えて、ローカルの main に取り込みたいとき。
- 新しい worktree でライブラリの導入などの準備を自動で済ませたいとき。
- 開発サーバーが何本も動いていて、どれがどの作業フォルダのものか分からなくなったとき。

## 画面のどこにあるか

- 「プロジェクト」→「worktree」タブ: 一覧、作成欄、各 worktree の操作。
- セッションの画面のターミナルのメニュー（「その他の操作」）: 「worktree を main にマージ…」、
  「実行スクリプト (.operon/run.sh) を起動…」、「実行スクリプトを停止」、「チェックポイント」。
- ターミナルの上のポートの表示: 「プロジェクトで N ポート稼働中」のような印から一覧を開きます。

## 今できること

- 新しい branch 名を入れて「worktree を作成」。プロジェクトの本流（`origin/HEAD`、無ければ `origin/main`・`origin/master`・`main`・`master`）から作り、
  どれから作ったかを知らせる。名前が使われていれば `name-2`、`name-3` と番号を足す。
- 一覧は「メインの worktree」と「追加の worktree」に分かれ、branch 名（無ければ「detached HEAD（ブランチ未設定）」）が出る。
  各行で「この場所で新規セッション」、Finder で表示、外部エディタで開く。
- 「削除…」で worktree を消す。確認が出て、branch は残ります。
- 「main にマージ…」で、その branch を本流に `--no-ff` でマージする。
  競合したら取り消して元に戻し、競合したファイルを知らせる。成功したら、チェックを外さない限り worktree とマージ済みの branch も削除する。
- `.operon/setup.sh` があるリポジトリでは、worktree の作成後に冒頭の数行を見せて
  「このリポジトリのセットアップを実行しますか？」と尋ねる。「実行する」で専用のセッションで動かし、「実行しない」でやめる。
  「内容が変わるまで、今後は確認しない」を選ぶと、その内容のスクリプトだけは次から尋ねない。
- `.operon/run.sh` があれば、「実行スクリプト (.operon/run.sh) を起動…」を押すたびに「実行スクリプトの確認」で内容を見せ、
  「承認して実行」で専用のターミナルで動かす。「実行スクリプトを停止」で止める。
- 「チェックポイント」で「手動チェックポイントを作成」、直近 5 件の一覧、その時点との差分のコピー、「チェックポイントへロールバック」。
  ステータスフックをオンにした worktree のセッションでは、依頼を送るたびに自動でも記録されます。
- 稼働中のポートを、作業フォルダの「この作業フォルダ」と「プロジェクト内のほかの場所」に分けて見て、
  ブラウザで開く、URL をコピーする、「停止する」で止める（確認に PID とフォルダが出ます）。

## 今できないこと・既知の制約

- 削除できるのは、変更がなく、使用中のセッションが無い worktree だけです。メインの worktree は削除できません。
- マージは次のとき断ります。どちらかのツリーに未コミットの変更がある、メインで別のマージが進行中、
  メインが本流以外の branch にある、その worktree かメインに実行中・順番待ちのセッションがある、取り込むコミットが無い。
- マージはローカルだけです。push や PR は別の操作です。
- 本流が見つからないリポジトリ（上の 5 つがどれも無い）では worktree を作れません。今チェックアウトしているものから勝手に作ることはしません。
- セットアップや実行スクリプトは 64 KiB までで、それを超えると実行しません。許可したあとに内容が変わったら実行せず、もう一度確認を求めます。
- 許可を覚えるのは「そのプロジェクトの、その内容」だけで、場所や名前では覚えません。
- ロールバックは追跡中のファイルをすぐ戻します。そのあとに作られた新しいファイルは消えません。
  チェックポイントの差分のコピーは 1 MB までです。
- ポートの停止は終了シグナル（SIGTERM）を送るだけで、Operon の外で起動したプロセスも対象です。
  持ち主を確かめられなかったときや Operon 自身などは停止しません。ポートの一覧は 30 秒ごとに更新し、最大 200 件です。
- Finder と外部エディタを開く以外に、worktree をほかの場所へ移す操作はありません。
