# 要対応

## 何のための機能か

エージェントが質問や許可の確認で止まっているとき、あなたがそれに気づかないまま時間が過ぎないようにする機能です。待っているセッションを「待ちの長い順」に 1 か所へ集め、その場で返事を送り、別のアプリを使っている間も画面の外から知らせます。

## 誰がいつ使うか

- 何本ものエージェントを同時に走らせ、どれが自分の返事を待っているのか探したくない人が使います。
- 席を離れる、別のアプリで作業するなどして、ターンの終わりや質問を見逃したときの拾い直しにも使います。

## 画面のどこにあるか

- **ツールバー**: 待っているセッションがあるときだけ「要対応 N」(キーを割り当てていれば「⌘J」も)が出ます。ポインタを置くと「次の要対応セッションへ移動します」と出ます。誰も待っていなければ消えます。ゼロは行動の対象ではないためです。
- **セッションページの履歴の一覧(「プロジェクト別」表示)**: 先頭に「要対応」の枠と件数があり、待っているセッションが待ちの長い順に並びます。各行に返信欄があります。
- **セッションページの左の列**: 上部の「要対応」タイルが件数を示し、押すとその状態だけに絞れます。プロジェクトの見出しにも「要対応」の件数が付きます。
- **ホーム**: 待っている数と最大 5 件の行を、見出しの直下に出します。
- **Dock のアイコン**: 待っているセッションの数が赤いバッジで出ます。
- **画面の右下**: 短い通知(「返信を送りました」など)が数秒だけ出ます。

## 今できること

- 待っているセッションを、待ちの長い順に確認する。各行には待ち時間(「たった今」「12分」「2時間」)、題名、プロジェクトとブランチ、エージェントの印が出ます。
- エージェントが言い終えている場合はその最後の言葉を、質問や許可待ちなら「許可または回答を待っています」を、行の下に最大 2 行まで添えます(フックで状態を取っているときだけ)。
- 行を押すか ⌘J を押して、その待ちのセッションを開く。ターミナルが動いていれば、キーボードがそのターミナルに入った状態で開きます。⌘J は次の待ちへ順に進み、最後まで行くと先頭へ戻ります。
- 行の返信欄に入力して Enter を押し、画面を動かさずに返事を送る。「はい」で質問に答え、「2」で 2 番目の選択肢を選べます。送ると「返信を送りました」と出ます。
- 日本語入力の変換を確定する Enter では送られません。変換が終わったあとの Enter で送ります。
- 待っているセッションの数を、Dock のバッジで確認する。誰も待っていなければバッジは消えます。
- 「設定 → 通知」をオンにすると、ターンの完了と入力待ちを macOS の通知で受け取る(「Claude Code が入力を待っています: セッション名」の形)。
- 別のセッションを見ている間にターンを終えたセッションは、開くまで「未読」の印が付き、要対応に数えられます。「未読にする」で自分でも印を付け直せます。

## 今できないこと・既知の制約

- 返信欄はターミナルが動いているセッションの行にだけ出ます。止まっているセッションには出ません。
- 返信は前後の空白を除いて送るため、空の Enter だけは送れません。そのような確認はセッションを開いて答えます。
- 質問をよく読む必要があるときは、返信欄ではなくセッションを開いてください。返信欄はその質問を表示しません。
- 書きかけの返信は、そのセッションが待ちでなくなると消え、アプリを再起動しても残りません。
- 行に出る「最後の言葉」は、新しい待ちに入ってからフックが報告した内容だけです。画面の読み取りだけで状態を取っているときは出ません。
- Dock のバッジは、macOS アプリとして起動したときだけ付きます(開発用の起動では付きません)。
- 左の列そのものには待ち時間つきの行や返信欄は並びません。それらは履歴の一覧にあります(取扱説明書の「列の先頭に固定」という書き方とは、現在のコードでは食い違っています)。
- 未読の印と待ち時間の計時は、再起動後には引き継がれません。
- 正常終了や自分で止めたセッションは要対応に残りません。異常終了は、タブが開いているか未読のあいだだけ要対応に残ります。
- 通知は、画面の読み取りだけで見ているセッションの「最初の読み取り」では出しません(再起動直後に完了を誤って知らせないため)。
