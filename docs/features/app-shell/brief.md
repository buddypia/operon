# アプリの土台

## 何のための機能か

Operon を起動してから閉じるまでの、すべての画面に共通する部分です。
起動の手順（PATH の補い、フォント、ウィンドウの大きさ、多重起動の防止）、上部のツールバー、ページの並び、通知の表示、ボタンや見出しなどの共通の部品、テーマの色が含まれます。
どの画面でも同じ見た目・同じ操作感になるのは、この土台のおかげです。

## 誰がいつ使うか

- Operon を起動するたび（Finder、Dock、ターミナルの `open -a Operon` のどれからでも）。
- Codex や Claude Code が「見つからない」と言われ、原因（PATH）を調べるとき。
- 画面のどのページでも、ツールバーからページを移るとき。
- フォルダをウィンドウへドラッグして、プロジェクトを追加するとき。

## 画面のどこにあるか

ウィンドウの上端に高さ 52 の細いツールバーがあり、タイトルバーの代わりにもなります（左に信号ボタン、右にドラッグで動かせる余白）。
左から順に、ブランド（押すとホーム）、「ホーム」「プロジェクト」「セッション」のページ切り替え、右側に「設定」の歯車、「検索・操作」（⌘K）、「新しいセッション」（⌘N）、待っているセッションがあれば「要対応 N」（⌘J）が並びます。
その下の領域に、選んだページの内容が出ます。「セッション」と、ファイルを開いたプロジェクトは画面いっぱいに広がり、ほかのページは左右に余白を取ります。
操作の結果の短い通知は画面の隅に出て、4 秒ほどで消えます。失敗は閉じるまで残ります。

## 今できること

- 起動すると、`PATH` に `/opt/homebrew/bin`、`/usr/local/bin`、`~/.local/bin`、`~/.cargo/bin` が無ければ補って、CLI を探す。Finder から起動しても Homebrew 等の CLI が見つかる。
- 初期のウィンドウは 1280×820。最小は 760×540。ウィンドウの位置や大きさは記憶しない。
- 日本語・韓国語を含む同梱のフォント（Sarasa 系）とアイコン用のフォントを内蔵しているので、環境にフォントが無くても文字とアイコンが欠けない。
- 同じデータフォルダを使う Operon を 2 つ同時に動かせない。2 つ目は「Operon は既に開いています」と出て終了する。
- 起動前の古い記録の取り込みに失敗したときは、「Operon は既存データを取り込めませんでした」と出て、既存のデータは変更しない。
- フォルダをウィンドウへドロップすると、プロジェクトを追加できる（新しいセッションの入力中は、そのセッションのプロジェクトになる）。ドラッグ中は「フォルダをドロップしてプロジェクトを追加」と出る。
- テーマ（ダーク・ライト・ハイコントラスト）を変えると、全画面と開いているターミナルの色がすぐ変わる。
- どの画面のボタンも、決まった高さ（通常 28、小さいものは 24）、同じ余白、同じフォーカスの見え方になる。
- ウィンドウが背面にあるときは、セッションの状態確認を 2 秒ごとから 6 秒ごとに減らして、CPU と電池を節約する。前面に戻ると、すぐ読み直す。
- アプリを閉じると、実行中のターミナルの購読、タブの並び、ダウンロード中のモデルを整理して終了する。
- `Operon knowledge search ...` と `Operon agents ...` は、画面を開かずに端末から実行できる。

## 今できないこと・既知の制約

- `nvm` 配下など、上の 4 か所以外に入れた CLI は、Finder から起動したアプリには見えないことがあります。そのコマンドが動くシェルから起動するか、`~/.local/bin` に置いてください。
- 複数ウィンドウは使えません（1 つのデータフォルダにつき 1 つのアプリだけ）。
- ウィンドウの位置と大きさは保存されません。
- 非対応のプラットフォームでは動きません（macOS 専用）。
- 起動に必要なツールが無い状態でも画面は開きます。tmux が無いと、セッションは起動できません（設定の「エージェント」で案内されます）。
- テーマ・色・文字サイズ・ボタンの高さは、決まった一覧にあるものだけが使えます。画面ごとの独自の色や大きさは作れません。
