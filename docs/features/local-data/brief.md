# データの保存場所とプライバシー

## 何のための機能か

プロジェクトとセッションの記録を、この Mac の中だけに、途中で電源が切れても壊れない形で保存する機能です。
Operon にはテレメトリ・アカウント・クラウドサービスがなく、記録は外へ送られません。
古い版からの引き継ぎ、壊れた記録の退避、tmux セッションの探し直しも、ここで受け持ちます。

## 誰がいつ使うか

- 普段は意識せず、プロジェクトを足したりセッションを起動したりするたびに自動で保存されます。
- 記録の場所を確認したい、バックアップを取りたい、データを消したいとき。
- 改名前の版（「xirp-copy」）から更新した人が、記録を引き継ぎたいとき。
- Operon を終了したあとや、Mac を再起動したあとに、tmux のセッションが記録と食い違ってしまったとき。

## 画面のどこにあるか

「設定」→「データと復旧」に、データフォルダの場所が表示されます。「データフォルダを表示」で Finder が開きます。
その下の「ターミナル復旧」にある「tmux をスキャン」で、記録から漏れた tmux セッションを探せます。
保存や引き継ぎに問題があったときは、画面の通知や、ウィンドウが開く前のダイアログで知らされます。

## 今できること

- 記録は `~/Library/Application Support/com.local.operon/` の「store-v2.json」に、書きかけを残さない方法で保存される。保存の途中で止まっても、直前の完全な記録が残る。
- ディスクへの確定を確認できなかったときは、「変更は書き込まれましたが、ディスクに保存されたことを確認できませんでした。…確認が済むまで強制終了しないでください。」と警告し、自動で再試行する。
- 停止の指示（セッションの停止中であること）も別のファイルに記録され、保存の途中で落ちても、再起動後に続きから処理できる。
- 起動時に、同じデータフォルダを使う Operon が 2 つ動かないように排他する。2 つ目は「Operon は既に開いています」と表示して終了する。
- データフォルダを作れない、ロックできない場合は「Operon はローカルデータを開けませんでした」と表示し、権限と空き容量の確認を案内する。
- 改名前の版（「xirp-copy」）や古い形式の記録は、初回起動時に取り込む。取り込み元の元データは変更しない。
- 保存データが読めなかったときは、「store.corrupt-…json」として脇に退避し、空の記録で起動する。退避先は通知で伝え、プロジェクトのファイルには触れない。
- 手元データの一覧: store-v2.json（プロジェクト・セッション・設定）、停止の記録、記憶した起動オプション、並び順、アカウント、keybindings.json、diff のメモ、承認済みスクリプト、管理フック、Handoff アーカイブ、ナレッジ、モデル、多重起動ロック。
- Operon を消すときは、データフォルダを削除すれば記録も消える。

## 今できないこと・既知の制約

- 新しい版の Operon が書いた記録（スキーマが新しいもの）は、古い版では読めません。読めない記録は退避され、空の記録で起動します（元のファイルは消さず、そのまま残ります）。
- データフォルダは 1 つの Operon しか使えません。インストール済みのアプリと `cargo run` の版も同時には動きません。
- 改名前の版の記録の取り込みは、現在の記録がまだ無いときの 1 回だけです。複数の候補があるときは、見つかった最初のものだけを使います。
- 退避も移動もできなかったときは、元の記録を上書きしないため、新しい変更は別名のファイル（store.recovery-…json）に保存されます。
- tmux セッションの探し直しは、手動の「tmux をスキャン」だけです。登録済みのプロジェクトに含まれない作業フォルダのセッションは引き継げません。
- 外部コマンド（tmux・git など）は時間と出力の上限つきで実行されます。上限を超えると「コマンド出力が安全上限の … KiB を超えました」で止まります。
- バックアップや同期、別の Mac への移行の機能はありません。
- Operon は、会話の復元のために各エージェントの記録フォルダ（`~/.claude/projects`、`~/.codex` など）を読み取りますが、アップロードはしません。

## 関連する変更

- 変更 243: 保存の途中のあらゆる中断（クラッシュ・ディスク確定の失敗）でも、確定済みの記録が失われないことを全パターンで検証した。
- 変更 045: 強制終了や再起動のあとでも、保存された会話 ID から壊れずに再開できるようにした。
- 変更 123: tmux のサーバーが無くなっていても、セッションを削除でき、画面にエラーが出続けないようにした。
- 変更 291: 強制終了・異常終了したセッションを、保存済みの会話 ID から同じタブで自動復元するようにした。
- 変更 303: ターミナルのペインが消えていても、セッションの復旧か新しいターミナルへ進めるようにした。
- 変更 270: アプリを終了しても、タブの並びを次の起動で復元するようにした。
- 変更 142: ナレッジの意味検索を、外部ツールに頼らず Operon 自身が持つモデルで行うようにした。
- 変更 307: 差分表示のレイアウトとプロジェクトの記録が、読み込みをまたいで保たれることを検証した。
