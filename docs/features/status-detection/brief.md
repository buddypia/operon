# 状態の検知

## 何のための機能か

エージェントが今「作業中」なのか、「アイドル」で次の依頼を待っているのか、「要対応」で人の答えを待っているのかを、
自動で見分けます。その結果が、一覧の印、作業時間、macOS の通知、Dock のバッジのもとになります。

## 誰がいつ使うか

複数のエージェントを並べて動かしているときに、どれに手を入れるべきかを一目で知るために使います。
特別な操作は要りません。設定でフックをオンにしておくと、判定がより正確になります。

## 画面のどこにあるか

- セッションページの左の列と、タブの状態の印。ホバーすると詳細が出ます。
- 見出しの「要対応」「実行中」「アイドル」の 3 つのトグルと件数。
- 作業中のペインの見出しと行の「実行中 · 12分」のような作業時間。
- 設定の「エージェント」にある「エージェント CLI のフックで状態を検知する」と、各ツールの行の「フック 導入済み」「フック 未導入」「フック 失敗」。
- 設定の「通知」にある「ターンの完了・入力待ち・終了を通知する」。

## 今できること

- 状態を 3 つのグループで示します。
  - 「要対応」: 回答待ち、自動復元できなかった異常終了、前提が失敗して止まっているもの。
  - 「実行中」: 起動中・作業中・停止処理中・順番待ち。
  - 「アイドル」: ターンを終えて次の依頼を出せるもの。
- 起動してまだ最初の依頼を受けていない Claude Code と Codex のセッションは「未開始」と表示し、印は中央の点になります。最初の依頼を送ると消え、`/clear` で戻ります。
- 状態の取り方は 2 つあります。
  - フック: Claude Code・Codex・Antigravity それぞれの設定に Operon 用の小さな項目を足し、CLI 自身に作業中・待機・完了を報告させます。オフにすると、足した分だけが取り除かれます。既存の項目は触りません。
  - 画面の読み取り: フックがないときは、ターミナル下部の数行から「esc to interrupt」などの表示を読んで判定します。
- フックの報告は 30 分間は画面より優先されます。30 分更新がなければ画面の読み取りに戻ります。
- 作業中のセッションは 1 分たつと作業時間を表示します（「12分」「1時間」）。今のターンの時間で、再起動すると数え直します。
- ターンが終わったとき、入力待ちで止まったとき、終了したときに macOS の通知を出せます。初めてオンにすると macOS が許可を求めます。
- 初回起動時の「このフォルダを信頼しますか」にだけ、設定の「初回起動時のフォルダ信頼プロンプトを自動承認する」をオンにしていれば自動で答えます。ほかの質問には答えません。
- Dock のアイコンには、待っているセッションの数がバッジで出ます。

## 今できないこと・既知の制約

- 画面の読み取りは各 CLI が今出している文言に頼ります。文言が変わると、完了の通知が出なくなる方向で外れます。
- 画面の読み取りで作業中から抜けるには、続けて 2 回同じ結果が出る必要があります。1 回だけの描画の途中では切り替えません。
- Operon を起動した時点で動いていなかったセッションは、「完了した」とは通知しません（最初の読み取りは基準として扱います）。
- 「未開始」は Claude Code と Codex だけです。
- 作業時間は 1 分未満は表示せず、再起動をまたいで引き継ぎません。
- 通知は設定でオンにしたときだけ出ます。
- 質問の文言は CLI ごと・版ごとに違うため、画面からは「信頼の確認」と番号付きの はい／いいえ の形だけを質問として扱います。
