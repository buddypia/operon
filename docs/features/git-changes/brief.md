# 変更・コミット・PR

## 何のための機能か

エージェントが作業ツリーに加えた変更を、Operon の中で読み、問題なければ選んだものだけをコミットし、
必要なら push して PR にするまでを 1 か所で済ませます。ターミナルに戻らなくても、
「読む → 直す → 記録する」が続けられるようにするための画面です。

## 誰がいつ使うか

- エージェントの作業が一段落して、何が変わったかを確かめたいとき。
- 変更のうち一部のファイルだけをコミットしたいとき。
- コミットする前に、AI に差分を見てもらいたいとき。
- できあがった branch を push し、GitHub の PR にしたいとき。

## 画面のどこにあるか

「プロジェクト」ページでプロジェクトを開き、「変更」タブを選びます（変更のあるファイル数がタブに出ます）。
タブの下に「変更ファイル」「差分」「コミット履歴」の切り替えと、更新ボタンがあります。

- 「変更ファイル」: 左に変更されたファイルの一覧とコミット欄、右に「作業ツリーの差分」。
- 「差分」: 差分だけを全幅で見る。
- 「コミット履歴」: 最近のコミットの一覧。
- 開いている PR の一覧は、隣の「PR」タブにあります。

## 今できること

- 一覧の各ファイルにチェックを入れて、次のコミットに含めるものを選ぶ。
  追跡中のファイルの変更は最初からチェック済み、新しいファイル（未追跡）は未チェックで始まります。
- ファイル名を押すと、右の差分がそのファイルだけになる。「すべて表示」で全体に戻る。
- 鉛筆のアイコンで、そのファイルを「ファイル」タブのエディタで開く。
- 差分はファイルごとに折りたため、両側の行番号が付き、書き換えた行は変わった語に印が付く。
  見出しに「3 ファイル +16 -2」のような合計が出る。
- 各ブロックの見出しにある「ステージ」「破棄」で、そのブロックだけを index に入れる、または捨てる。
  「破棄」は確認なしで実行されます。
- 「コミットメッセージ」を書いて「N ファイルをコミット」でコミットする。
  「AI に書かせる」を押すと、チェックしたファイルを index に入れたうえで、使えるエージェントがその内容から下書きを入力欄に書く（自動ではコミットしません）。
- コミットに失敗したら「コミット失敗: …」と短い理由が出て、「AI で修正」でエージェントに直させられる。
- 「push」の行で、upstream との差（先行・遅れ）を確かめ、「push」ボタンで送る。
  新しい branch は origin に upstream を付けて送ります。
- 「AIレビュー」で、エージェントが差分をレビューする。結果は枠に出て、「コピー」「閉じる」ができる。
- 「PR を作成…」でタイトル・説明・「下書き (Draft PR) として作成」を選んで GitHub の PR を作る。
- 「PR」タブで、オープン中の PR を番号・branch・レビューと CI の要約付きで見て、ブラウザで開く。

## 今できないこと・既知の制約

- force push はありません。リモートが先に進んでいるときの push は「リモートが進んでいます。先に pull してください。」と断られます。
- Operon に pull の操作はありません。
- コミットはファイル単位です。`git add -p` などターミナルで作った一部だけの staging が残っていると、
  それを壊さないために断られます（Operon の「ステージ」で入れたブロックは守られます）。
- 差分が 180,000 バイト（表示は 175 KiB）を超えると、そこで切り詰めて「差分を … KiB で切り詰めました」と出ます。
- 「AIレビュー」は 45 秒、AI のメッセージ下書きは 120 秒で打ち切ります。
  レビュー対象の差分が空のときは実行されません。使えるエージェントが無ければ「AI に書かせる」は出ません。
- 「AI でドラフト生成」（PR）は AI に頼むのではなく、差分の冒頭 500 文字を説明欄に入れるだけです。
- 「PR を作成…」は GitHub CLI（`gh`）が入っているときだけ出ます。branch は先に push しておく必要があり、Operon が黙って送ることはありません。
- 「PR」タブは最大 30 件、オープン中のものだけです。
- 他のコミット・push・マージが進行中のときは、ボタンが押せないか「Git の操作が既に実行中です。」と出ます。
- 「ステージ」「破棄」は、作業ツリーとの比較（HEAD と手元）のときだけ出ます。
