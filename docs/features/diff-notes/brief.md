# diff へのメモと比較

## 何のための機能か

差分を読みながら気づいたことを、その行に書き留め、まとめてエージェントに返せるようにします。
「どの行の何が問題か」を取り違えなく伝えるためのものです。
もう 1 つ、ファイルを過去の状態と並べて見比べる「比較バー」と、行ごとに誰がいつ書いたかを見る「注釈」も、
同じ画面にあります。

## 誰がいつ使うか

- エージェントの変更をレビューして、複数の指摘を一度に返したいとき。
- 後で直すつもりの気づきを、行に付けて残しておきたいとき。
- あるファイルが昔どうだったか、ある 1 つのコミットで何が変わったかを確かめたいとき。

## 画面のどこにあるか

- メモ: 「プロジェクト」→「変更」タブの差分と、「ファイル」タブでファイルを開いたときの「差分」表示の中です。
  メモは書いた行のすぐ下に出ます。メモが 1 件以上あると、差分の下に 1 本のバーが出ます。
- 比較バー: 「ファイル」タブでファイルを開き、表示を「差分」に切り替えると、その上にあります
  （「比較:」の右に選択ボタン、「左右」「統合」の切り替え、変更の前後に移る矢印）。
- 注釈: 同じ切り替えの「注釈」を選ぶと、各行の左にコミットの短い ID・日付・書いた人が並びます。

## 今できること

- 差分の、変更後に存在する行をクリックして「この行について書く」欄にメモを書き、「保存」する。
  空のまま保存するか「削除」を押すとメモは消えます。
- メモは保存され、アプリを再起動しても残る。
- メモのバーに「3 件（未解決 2、送信済 1、解決済 0）」のように件数が出る。
- 「セッションにまとめて送る」で、未解決のメモを 1 通のメッセージにして、そのプロジェクトで動いている最新のエージェントへ送る。
  各メモは「File: パス / Line: 行 / User comment: 本文」の形で、空行で区切られます。
- 送ったメモは消えずに「送信済み」の印が付く。各メモの「解決」「再開」で解決済みにしたり戻したりできる。
- 「Markdownをコピー」でメモ全体を Markdown でコピーする。「解決済みを消去」「すべて消す」で片付ける。
- 書いたあとに行の内容が変わっていたら、メモに「行が変わっています」と出て、送るメッセージにもその旨が添えられる。
  メモが勝手に別の行へ移ることはありません。
- 比較バーで、HEAD（最新コミット）の代わりに、そのファイルの過去のコミットを選んで「リビジョン ↔ ローカル」を比べられる。
  選べる履歴はそのファイルの最新 200 件までです。
- 「このコミットの変更を表示」で 1 つのコミット自身の変更（親 ↔ そのコミット）を見て、「HEAD と比較に戻る」で戻る。
- 「左右」（2 列で並べる）と「統合」（1 列）を切り替える。選んだ表示は覚えておく。
  幅が狭いときは自動で「統合」になります。
- 矢印と F7（前は ⇧F7）で前後の変更ブロックに移り、「2 / 5」のように位置を見る。
- 注釈で、行を押すとメニューが開き、そのコミットとの比較や、コミットハッシュのコピーができる。
  行にマウスを載せると、コミットの要約が出ます。

## 今できないこと・既知の制約

- メモの本文は 2,000 文字までです。送るメッセージ全体は 32 KiB までで、超えると「コメントが大きすぎて一度に送れません」と出て、送られません。
- 動いているエージェントのセッションが無いときは送れません（「このプロジェクトで動いているエージェントのセッションがありません。」）。
  エージェントが作業中のときは「エージェントの応答が終わるまで待ってください。」と出て、送りません。
- メモを書けるのは「HEAD と手元」の比較のときだけです。過去のリビジョンとの比較や、1 つのコミットの表示では書けません
  （ブロックの「ステージ」「破棄」も出ません）。
- 送った後でも、解決済みにしていないメモは、もう一度送ると再び含まれます。
- メモの保存ファイルが壊れて読めないときは、メモを空として扱い、壊れたファイルは別名で脇によけます。上書きして失うことはしません。
- 注釈は、まだコミットされていないファイルでは「このファイルはまだコミットされていません。」と出るだけです。
  4 MiB を超える出力のときは、一部だけは見せず「大きすぎるため注釈を表示できません」と出ます。
- 比較できるのはプロジェクトのフォルダの中のテキストファイルです。
