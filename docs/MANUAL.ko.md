# Operon 사용자 매뉴얼

Operon은 AI 코딩 에이전트(Claude Code, Codex CLI, Antigravity CLI 또는 임의의 사용자 지정 명령)를
실행하고 감독하기 위한 로컬 우선(local-first) macOS 앱입니다. 각 에이전트는 독립된 `tmux` 세션에서
실행되므로 앱을 종료해도 작업은 계속됩니다.

이 매뉴얼은 일상적인 사용법을 다룹니다. 기능 개요는 [README.ko.md](../README.ko.md),
기여 방법은 [CONTRIBUTING.ko.md](../CONTRIBUTING.ko.md)를 참고하세요.

> **화면 표시 이름에 대하여.** Operon의 화면은 한국어·English·日本語로 표시할 수 있지만, 아직 번역되지
> 않은 라벨이 있습니다. 번역되지 않은 라벨은 어느 언어에서든 일본어로 표시됩니다. 이 매뉴얼에서
> **굵은 글씨**(예: **새 세션**)는 한국어 화면에서 실제로 보이는 라벨입니다. 아직 번역되지 않은 라벨은
> **停止**(중지)처럼 화면에 보이는 일본어 뒤에 뜻을 적었습니다.

## 1. 설치

### 요구 사항

| 요구 사항 | 비고 |
| --- | --- |
| macOS 12 이상 | Apple Silicon 또는 Intel(패키징된 번들의 최소 버전은 12.0) |
| Rust 툴체인 | 소스에서 빌드할 때만 필요. [rustup](https://rustup.rs/)으로 설치 |
| `tmux` | 세션 실행에 필수. `brew install tmux` |
| 에이전트 CLI 1개 이상 | `claude`, `codex`, `agy`(Antigravity)가 `PATH`에 있어야 함. 사용자 지정 명령도 가능 |
| `gh`(선택) | **PR** 탭에서 열린 PR 목록을 볼 수 있습니다 |

### 소스에서 빌드하고 실행

```sh
git clone https://github.com/buddypia/operon.git
cd operon
cargo run --release
```

이미 설치된 Operon이 있다면 종료한 뒤 실행하세요(반대의 경우도 마찬가지입니다).
자세한 내용은 [중복 실행 잠금](#10-문제-해결)을 참고하세요.

### macOS 앱으로 패키징

```sh
bash scripts/package-macos.sh
```

스크립트는 먼저 `cargo fmt --check`, `cargo test --locked`,
`cargo clippy --locked -- -D warnings`를 실행한 다음, 의존성을 고정한 상태로 빌드해
`dist/Operon.app`을 만듭니다. `/Applications`는 건드리지 않으므로 필요하면 번들을 직접 복사하세요.

이 번들은 **ad-hoc 서명**입니다. 빌드한 Mac에서는 실행되지만 Developer ID로 서명되거나 공증
(notarization)되지 않았습니다. 다른 Mac에서는 Gatekeeper가 처음에 실행을 거부합니다.
*우클릭 → 열기* 또는 *시스템 설정 → 개인정보 보호 및 보안 → 그래도 열기*를 사용하세요.
다른 사람에게 제대로 배포하려면 Apple Developer ID 인증서와 공증이 필요합니다.

### 첫 실행

프로젝트가 하나도 없으면 **프로젝트** 페이지에 **먼저 프로젝트를 여세요**와
**첫 세션을 시작하기 전에** 체크리스트(`tmux`와 코딩 에이전트, 두 줄)가 표시됩니다.
둘 중 하나라도 없으면 **설정 절차 열기**로 **설정 → 에이전트**에 이동할 수 있습니다. 그곳에서는
각 도구의 상태(머리글에 `n/6` 사용 가능), **도구 다시 확인** 버튼, 각 CLI의 설치 안내를 여는
**설치 방법** 버튼을 쓸 수 있습니다.

Finder에서 실행한 앱은 `PATH`가 짧지만, Operon은 스스로 `/opt/homebrew/bin`, `/usr/local/bin`,
`~/.local/bin`, `~/.cargo/bin`을 `PATH`에 추가하므로 그 위치의 도구는 찾을 수 있습니다.

## 2. 기본 개념

- **프로젝트** — 로컬의 임의 폴더. Git 체크아웃이면 Git 기능도 사용할 수 있고, 에이전트 실행과
  파일 탐색은 어떤 폴더에서든 됩니다. 프로젝트를 추가해도 폴더는 수정되지 않으며, 삭제하면
  Operon의 기록만 지워집니다(파일, branch, worktree는 그대로 남습니다).
- **세션** — 하나의 에이전트가 하나의 `tmux` 세션에서 실행되는 상태. 이름은 `operon-` 뒤에 8자가
  붙는 형태입니다. 세션은 프로젝트에 속하며 worktree에서 실행할 수도 있습니다.
- **worktree** — 같은 저장소를 다른 branch로 한 번 더 체크아웃한 것. 여러 세션이 서로의 파일을
  건드리지 않고 병렬로 작업할 수 있습니다.
- **에이전트** — 세션이 실행하는 도구: **Claude Code**, **Codex CLI**, **Antigravity CLI (agy)**
  또는 사용자 지정 명령. (내부 저장값은 예전 이름인 `gemini`이지만, 화면과 문서에서는 Antigravity라고
  부릅니다.)

창은 도구 모음과 네 개의 페이지로 구성됩니다.

- **홈**(⌘1) — 지금 실행 중인 것, 사용자를 기다리는 것, 최근 세션, 프로젝트별 시작 버튼.
- **프로젝트**(⌘2) — 프로젝트 목록. 하나를 열면 **概要**(개요), **변경**, **worktree**, **PR**,
  **파일**, **에이전트 설정** 탭이 나타납니다.
- **세션**(⌘3) — 왼쪽에 세션 목록, 오른쪽에 선택한 세션의 터미널.
- **설정**(⌘,).

도구 모음에는 **새 세션**(⌘N), **검색·작업**(⌘K), 설정 버튼이 있으며, 사용할 수 있으면 Claude 사용량
표시도 나타납니다.

## 3. 에이전트 세션 시작과 관리

### 프로젝트 추가

**프로젝트** 페이지에서 **프로젝트 폴더 선택…**(⌘O)을 누르거나 Finder에서 폴더를 창으로 끌어다 놓습니다.
**워크스페이스 스캔…**은 선택한 폴더 아래 3단계까지의 Git 저장소를 한꺼번에 가져옵니다.
**パスを手入力**(경로 직접 입력)에서는 절대 경로를 입력해 추가할 수 있습니다.

### 세션 시작

어느 페이지에서든 **새 세션**(⌘N)을 누르면 현재 페이지 위에 시트가 열립니다.

1. **에이전트** — Codex, Claude Code, Antigravity 또는 **別のコマンドを使う**(다른 명령 사용).
   녹색 표시는 이 Mac에서 사용할 수 있다는 뜻입니다. 사용자 지정 명령은
   **起動コマンド（必須）**(실행 명령, 필수)를 입력합니다.
2. **계정** — Claude Code와 Codex에서, 계정을 등록한 경우에만 표시됩니다([설정](#8-설정과-표시-언어) 참고).
   기본값은 **이 컴퓨터**입니다.
3. **요청(선택)** — 에이전트에게 시킬 일. 첫 메시지로 입력됩니다.
4. **작업 위치** — **프로젝트 루트** 또는 worktree(**워크트리: branch이름**으로 표시). worktree는
   프로젝트의 **worktree** 탭에서 만듭니다.
5. **상세 설정(선택)** — 기본적으로 접혀 있습니다. 세션 이름, 모델, CLI 자체의 권한 모드, **추론 깊이**,
   그 CLI가 받는 스위치, **ほかのセッションの後に開始**(다른 세션 뒤에 시작)가 들어 있습니다.

**〈에이전트〉 を起動  ⌘↩**(〈에이전트〉 실행)로 시작합니다. **ターミナルだけ開く**(터미널만 열기)는 에이전트 없이
일반 `tmux` 셸만 엽니다. **Esc** 또는 ✕는 시작하지 않고 시트를 닫습니다.

시트가 지키는 규칙:

- 모드, 추론 깊이, 스위치는 모두 해당 CLI 자체의 목록에서 고릅니다. Operon이 임의의 플래그를 만들지
  않습니다. CLI가 함께 쓰는 것을 거부하는 두 스위치는 동시에 켤 수 없습니다.
- 확인 없이 파일을 변경할 수 있는 스위치나 모드에는 **危険**(위험) 표시가 붙습니다.
  **理解したうえで起動する**(이해하고 실행)에 체크할 때까지 실행 버튼은 비활성 상태입니다.
  이런 플래그를 포함한 사용자 지정 명령에도 같은 확인이 적용됩니다.
- `tmux`나 에이전트가 없으면 그 사실이 표시되고 **설정 → 에이전트**로 가는 바로가기가 나옵니다.
- 마지막으로 쓴 모델, 모드, 추론 깊이, 스위치, 사용자 지정 명령은 에이전트별로
  `recent-agent-settings.json`에 기억됩니다.

### 세션을 순서대로 대기시키기

**상세 설정(선택)**의 **ほかのセッションの後に開始**(다른 세션 뒤에 시작)를 고르면 앞선 세션이 끝난 뒤에
시작됩니다. 대기 중인 세션에는 바로 실행하는 **今すぐ開始**(지금 바로 시작)가 나옵니다. 선행 세션이
실패하면 대기 중인 세션은 차단 상태가 되며 저절로 시작되지 않습니다.

### 중지 · 재시도 · 재개 · 닫기

세션 행의 모서리와 터미널 머리글의 버튼은 현재 상태에 맞는 동작 하나만 보여 줍니다.

| 상태 | 버튼 |
| --- | --- |
| 실행 중 | **停止**(중지). 기록은 남습니다. 중지가 끝나기를 기다리는 동안에는 **停止中…**(중지 중…)으로 표시되며, 다시 누르면 중지를 재시도합니다 |
| 대기열 | **今すぐ開始**(지금 바로 시작) |
| 실패/결과 불명이고 저장된 대화가 없음 | **다시 시도** — 이전 터미널을 안전하게 확인하고 정리한 뒤 다시 실행합니다 |
| 실패/결과 불명/종료/중지이고 저장된 대화가 있음 | **会話 ID から再開**(대화 ID로 재개). 마우스를 올리면 이어받는 모델, 모드, 스위치가 표시됩니다 |

그 밖의 동작:

- **名前を変更**(이름 변경): 세션 제목을 더블클릭하거나 `···` 메뉴에서.
- **읽지 않음으로 표시**: `···` 메뉴에서.
- **セッションを削除**(세션 삭제) — 행의 ✕. 실행 중인 터미널은 먼저 중지됩니다. 파일과 worktree는
  삭제되지 않습니다.
- **ターミナルを閉じる**(터미널 닫기) — 끝나거나 실패한 세션에 남은 터미널을 정리합니다.
- 터미널 머리글의 `···` 메뉴에는 **Terminal.app で開く**(Terminal.app에서 열기: 마우스 조작·`tmux` 조작용),
  **表示中のログをすべてコピー**(색상 코드 없이 버퍼 전체 복사), **今すぐ同期**(지금 동기화)가 있습니다.

### 터미널 패널

패널을 클릭하면 에이전트에 입력할 수 있으며, 일본어 IME 같은 입력기도 동작합니다. 앱 안의 스크롤백은
최대 5,000줄입니다(`tmux` 자체는 50,000줄 보관). **최신으로**를 누르면 가장 최근 줄로 이동합니다.
사이드 패널(화살표로 접고 **사이드 패널 표시**로 다시 엽니다)에는 **파일**, **대화**(지금까지 보낸 요청),
**변경** 세 탭이 있습니다.

터미널 출력의 경로는 링크가 됩니다. **⌥**를 누른 채 클릭하면 내장 편집기에서 해당 줄을 열고,
**⌘**를 누른 채 클릭하면 외부 앱으로 엽니다. 열 수 있는 것은 그 세션의 폴더 안에서 실제 파일로 확인되는
경로뿐입니다. dev server가 출력하는 주소도 같은 방법으로 브라우저에서 엽니다. 일반 클릭은 패널에
포커스만 주므로 에이전트와의 입력이 실수로 끊기지 않습니다.

## 4. 상태 감시와 알림

### 상태

모든 세션은 아래 네 가지 중 하나로 표시되며, 마우스를 올리면 자세한 설명이 나옵니다.

| 라벨 | 의미 |
| --- | --- |
| **대응 필요** | 답변을 기다리거나, 전제 조건이 실패해 멈춘 상태 |
| **실행 중** | 시작 중, 작업 중, 중지 처리 중, 대기열 |
| **대기 중** | 실행 중이며 다음 요청을 기다리는 상태 |
| **종료** | 터미널이 끝난 상태(정상 종료, 실패, 중지, 결과 불명) |

세션 목록 머리글에는 **대응 필요**, **실행 중**, **대기 중**, **종료** 네 개의 토글 칩이 있고 각각 건수가
표시됩니다. 켠 상태의 세션만 골라 볼 수 있으며, 숨겨진 건수가 표시되고 **フィルタを解除**(필터 해제)로
끌 수 있습니다. 필터는 재시작 후에는 유지되지 않습니다.

**홈**의 배너는 사용자를 기다리는 세션(답변 대기, 차단, 읽지 않은 완료)을 세고, 그 항목만 걸러 낸
목록을 엽니다. 다른 세션을 보는 동안 턴이 끝나면 그 세션을 열 때까지 표시가 남습니다.
**읽지 않음으로 표시**로 다시 표시할 수 있습니다. 이 표시는 재시작 후에는 남지 않습니다.

### 상태는 어디서 오는가

- **hook(권장).** **설정 → 에이전트**의 **에이전트 CLI의 훅으로 상태를 감지**를 켜면, 각 CLI 자체의 설정
  파일 — `~/.claude/settings.json`, `~/.codex/hooks.json`(신뢰 항목은 `~/.codex/config.toml`),
  Antigravity는 `~/.gemini/config/hooks.json` — 과 등록한 계정 폴더에 Operon용 작은 항목이 추가됩니다.
  그러면 CLI가 스스로 작업 중·대기·완료를 보고합니다. 기존 항목은 그대로 보존되며, 끄면 Operon이 추가한
  것만 제거됩니다. 각 도구 행에는 **훅 설치됨** / **훅 미설치** / **훅 실패**가 표시되고, 마우스를 올리면
  이유를 볼 수 있습니다.
- **화면 판독.** hook이 없거나 hook 보고가 30분보다 오래되었으면, 터미널 아래쪽 몇 줄을 읽어 작업 중인
  에이전트와 질문에서 멈춘 에이전트를 구분합니다.

같은 섹션의 **첫 실행 시 폴더 신뢰 프롬프트를 자동 승인**은 CLI의 "이 폴더를 신뢰합니까" 질문에만
답하며, 그 밖의 것은 승인하지 않습니다.

### 알림

**설정 → 알림 → 턴 완료·입력 대기·종료를 알림**을 켜면, 에이전트가 턴을 마치거나 프롬프트에서 멈추거나
종료할 때 macOS 알림이 표시됩니다. 처음 켤 때 macOS가 권한을 요청합니다.

### 그 밖의 표시

- 세션 머리글에는 그 세션의 worktree가 수신 대기 중인 포트가 `:5173 vite`처럼 표시됩니다. 클릭하면 열고,
  우클릭하면 URL을 복사합니다. 포트는 30초마다 `lsof`로 읽습니다.
- 도구 모음에는 Claude 사용량 한도를 얼마나 썼는지가 표시됩니다. Operon이 따로 요청을 보내지 않으며
  Claude Code가 이미 보고하는 값을 읽을 뿐입니다. 80%를 넘으면 호박색이 되고, 30분 넘게 갱신되지 않으면
  경과 시간과 함께 흐리게 표시됩니다.

## 5. Git · diff · 파일 · 편집기

프로젝트를 열고 그 탭을 사용합니다.

### 변경

**변경** 탭에는 **Changes**, **Diff**, **History** 세 가지 보기가 있습니다.

- **Changes**는 변경된 파일 목록입니다. 다음 commit에 포함할 파일에 체크합니다. 추적 중인 파일의 수정은
  처음부터 체크되어 있고, 추적되지 않는 파일은 체크 해제 상태로 시작합니다. 메시지를 쓰거나
  **AI에게 쓰게 하기**를 누릅니다(로컬 에이전트 CLI가 staged patch를 바탕으로 입력란에 초안을 씁니다.
  스스로 commit하는 일은 없습니다). 그런 다음 **N개 파일 커밋**을 누릅니다. `push` 줄은 upstream과의
  차이를 보여 주며, 원격이 앞서 있으면 push를 거부합니다. Operon에는 force push가 없습니다.
  commit은 체크한 파일만 다시 staging합니다. `git add -p`로 만든 hunk 단위 선택이 index에 남아 있으면
  그것을 망가뜨리지 않도록 거부합니다.
- **Diff**는 파일별로 접을 수 있게, 양쪽 줄 번호와 함께 그리며, 수정된 줄 안에서 실제로 바뀐 단어를
  표시합니다. **AI 리뷰**는 로컬 에이전트 CLI에 diff 리뷰를 요청하고(45초 제한), **복사**로 결과를
  복사합니다.
- **History**는 최근 commit을 보여 줍니다.

### diff에 메모 남기기

**Diff**에서 변경 후에 존재하는 줄을 클릭하면 그 아래에 메모를 쓸 수 있습니다(**この行について書く**:
이 줄에 대해 쓰기, **저장**). 메모는 디스크에 저장되어 재시작 후에도 남습니다. 하단에 건수(미해결·전송됨·해결됨)가
표시되고, **세션으로 한 번에 보내기**(모든 파일과 줄을 명시한 메시지 하나로 만들어 그 프로젝트에서 실행 중인
에이전트에 보냅니다. 에이전트가 턴 도중이면 거부됩니다), **Markdown 복사**, **해결된 항목 지우기**,
**모두 지우기**를 쓸 수 있습니다. 메모를 쓴 뒤 줄이 바뀌었다면 다른 줄로 조용히 옮겨 가지 않고
**行が変わっています**(줄이 바뀌었습니다)라고 표시합니다.

### worktree

**worktree** 탭에서는 새 branch 이름으로 worktree를 만들 수 있습니다. 프로젝트의 메인라인(`origin/HEAD`,
없으면 `origin/main`, `origin/master`, `main`, `master`)에서 만들어지며 어느 것을 썼는지도 표시됩니다.
이름이 이미 쓰이고 있으면 다음 번호(`name-2`, `name-3`…)가 쓰입니다. 각 worktree에는
**この場所で新規セッション**(이 위치에서 새 세션)과 **削除…**(삭제…)가 있습니다. 삭제할 수 있는 것은 변경이 없고
사용 중이 아닌 worktree뿐이며, 확인 후에 삭제되고 branch는 남습니다.

저장소에 `.operon/setup.sh`가 있으면, worktree를 만든 뒤 앞부분 몇 줄을 보여 주며
**이 저장소의 설정을 실행할까요?**라고 묻습니다. **실행하기**를 누르면 전용 세션에서 실행되며 지켜보거나
멈출 수 있습니다. **내용이 바뀔 때까지 다시 묻지 않기**에 체크하면 그 내용의 스크립트에 한해 승인이
기억됩니다. 한 글자라도 바꾸면 다시 묻습니다.

### PR

**PR** 탭에는 열린 GitHub PR이 리뷰와 CI 체크 요약과 함께 표시됩니다. GitHub CLI(`gh`)가 설치되어 있고
로그인되어 있어야 합니다.

### 파일과 편집기

**파일** 탭에는 접을 수 있는 프로젝트 트리(변경된 파일에는 Git 배지), 편집기 탭, 줄 번호, 구문 강조가
있습니다. **⌘S**로 저장합니다. Markdown은 Markdown으로 렌더링됩니다. 128 KiB를 넘는 파일은 읽기 전용으로
열리고, 10 MiB까지의 이미지는 미리 볼 수 있습니다. 트리는 `.git`, `node_modules`, `target`, `.next`를
건너뜁니다.

Operon은 에이전트의 작업을 조용히 덮어쓰지 않습니다. 연 뒤에 디스크에서 바뀐 파일에 저장하면 거부됩니다.
열린 파일은 2초마다 디스크와 비교되며, 저장하지 않은 편집이 없으면 자동으로 다시 불러오고 알려 줍니다.
저장하지 않은 편집이 있으면 다시 불러오기 또는 diff를 고르는 바가 나타납니다. **에이전트 설정** 탭에는
프로젝트의 skill과 지침 파일이 나열됩니다.

## 6. CLI 간 대화 복원

Claude Code, Codex CLI, Antigravity의 어떤 대화든 세 가지 중 어디로든 복원할 수 있습니다. 같은 CLI로
다시 복원하면 원래 대화에 영향을 주지 않고 분기됩니다. 복원은 각 CLI가 이미 로컬에 저장해 둔 transcript
파일을 읽어서 이루어집니다. **모델은 실행되지 않고 토큰도 소모되지 않으며** 요약도 하지 않습니다.

**세션에서**: 목록에 있는 세션의 `···` 메뉴에서 다른 CLI의 **〈에이전트〉 へ履歴を復元**(〈에이전트〉로 기록 복원)을
고릅니다.

**과거 대화에서**: **세션** 페이지에서 **기록**을 누르고 **CLI 세션(이전 대화 찾기와 복원)**을 펼친 뒤
프로젝트를 고르고 **ローカル CLI セッションを検出**(로컬 CLI 세션 검색)을 누릅니다. 각 카드에는 대화 ID,
branch, 마지막 요청이 표시됩니다. 그런 다음 다음 중 하나를 합니다.

- **元の CLI で再開**(원래 CLI에서 재개)
- **復元先**(복원 대상)을 고르고, 필요하면 **復元メモ（任意）**(복원 메모, 선택)를 쓴 뒤
  **会話全履歴を復元**(대화 전체 기록 복원)을 누르기

복원 중에는 원본 대화, 복원 대상, 경과 시간을 보여 주는 창이 나타나며 백그라운드로 보낼 수 있습니다.
같은 **기록** 페이지에는 **ローカル履歴**(로컬 기록)도 있어서 최근 Codex·Claude transcript를 전문 검색할 수
있습니다.

### 공유 세션 아카이브

복원할 때마다 원본 transcript가 `shared-sessions/<id>/source.jsonl`에 그대로 보관되고, 그 옆에
`manifest.json`과 읽기 쉬운 `restored-conversation.md`가 만들어집니다. 폴더는 `0700`, 스냅샷은 `0600`으로
만들어지므로 읽을 수 있는 것은 사용자 계정뿐입니다. 민감한 프롬프트, 도구 출력, 소스 코드가 들어 있을 수
있습니다.

| ⌘, | **설정** | |
| ⌘O | 프로젝트 폴더 선택 | |

단축키를 바꾸려면 **설정 → 키 할당**에서 **키 할당 파일 열기**를 누르세요. 처음에는 현재 키로
`keybindings.json`을 만들고 Finder에서 보여 줍니다. 이미 있는 파일을 덮어쓰는 일은 없습니다.
형식은 다음과 같습니다.

```json
{
  "version": 1,
  "keybindings": {
    "palette.open": "Mod+K",
    "terminal.find": "Mod+Shift+F",
    "page.settings": null
  }
}
```

`Mod`는 ⌘를 뜻하며 다른 보조 키는 `Shift`, `Alt`, `Ctrl`입니다. `null`은 키 없음입니다. 동작 ID는
`palette.open`, `session.new`, `page.home`, `page.projects`, `page.sessions`, `page.settings`,
`project.add`, `terminal.find`입니다. 한 키를 두 동작에 지정했거나 알 수 없는 동작이 들어 있는 파일은
파일 전체가 거부되고, 기본 키로 시작하면서 이유가 표시됩니다.

## 8. 설정과 표시 언어

**설정**(⌘,)에는 다섯 개의 섹션이 있습니다.

| 섹션 | 내용 |
| --- | --- |
| **모양** | **테마**(다크(기본)·라이트·하이 콘트라스트(다크). 열려 있는 터미널에도 즉시 적용), **터미널 및 코드 글꼴**(Sarasa 계열 4종), **언어** |
| **에이전트** | 도구 상태, hook 스위치, 폴더 신뢰 자동 승인, **에이전트 계정** |
| **알림** | 알림 스위치 |
| **데이터와 복구** | 데이터 폴더 경로, **データフォルダを表示**(데이터 폴더 보기: Finder에서 열기), 기록이 사라진 `tmux` 세션을 찾는 **tmux をスキャン**(tmux 스캔) |
| **키 할당** | 모든 단축키와 현재 키 |

**언어**: English, 日本語, 한국어 중에서 고릅니다. 변경은 다음 프레임에 적용되고 저장됩니다.
처음 실행할 때는 시스템 언어(`LC_ALL`, `LC_MESSAGES`, `LANG`, 그다음 macOS의 언어 목록)로 정해지며,
판별할 수 없으면 일본어가 됩니다. 표시 언어를 한국어로 해도 아직 번역되지 않은 라벨은 일본어로 표시됩니다.

**에이전트 계정**: 계정은 Codex나 Claude Code가 로그인 정보를 두는 폴더(`CODEX_HOME` /
`CLAUDE_CONFIG_DIR`)입니다. 에이전트를 고르고 이름(예: 업무)을 붙인 뒤 **フォルダを選んで追加**(폴더를 골라 추가)를
누릅니다. 이후 세션을 시작할 때 **계정**에서 고를 수 있습니다. Operon은 그 폴더를 CLI에 가리킬 뿐
내부를 읽지 않습니다. 관리형 hook도 같은 폴더에 설치됩니다. Antigravity에는 계정 기능이 없습니다.

## 9. 데이터 위치와 개인정보

모든 것은 로컬에서 동작합니다. Operon에는 텔레메트리, 계정, 클라우드 서비스가 없습니다. 에이전트는 별도의
도구로 실행되며 프로젝트 내용을 각 제공자에게 전송할 수 있습니다. 시작하기 전에 각 에이전트의 권한과
sandbox 모드를 확인하세요.

Operon의 데이터는 `~/Library/Application Support/com.local.operon/`에 있습니다(**설정 → 데이터와 복구**에
정확한 경로가 표시되며 Finder에서 열 수 있습니다).

| 항목 | 용도 |
| --- | --- |
| `store-v2.json` | 프로젝트, 세션, 설정(스키마 버전 포함, 원자적으로 기록) |
| `store-v2.json.pending-cancellations.json` | 진행 중인 중지의 영속 기록 |
| `recent-agent-settings.json` | 기억된 실행 옵션 |
| `agent-accounts.json` | 등록한 계정 폴더 |
| `keybindings.json` | 사용자 단축키(만든 경우) |
| `diff-comments.json` | diff에 쓴 메모 |
| `setup-trust.json` | 승인한 `.operon/setup.sh`의 다이제스트 |
| `agent-hooks/` | 관리형 hook 스크립트, endpoint 파일, 로컬 `hook.sock`(`0700`) |
| `shared-sessions/` | 복원 아카이브([6장](#6-cli-간-대화-복원)) |
| `.operon-instance.lock` | 중복 실행 잠금 |

Operon은 대화를 찾아 복원하기 위해 각 에이전트 자체의 transcript 폴더(`~/.claude/projects`, `~/.codex` 등)도
읽습니다(업로드하지 않습니다). Operon으로 이름을 바꾸기 전의 빌드는 `xirp-copy` 폴더에 데이터를 두었으며,
첫 실행 때 가져옵니다.

## 10. 문제 해결

**"`tmux`가 필요합니다"** — `brew install tmux`로 설치한 뒤 **설정 → 에이전트**에서 **도구 다시 확인**을 누르세요.

**에이전트를 찾을 수 없음("選んだ AI が見つかりません": 선택한 AI를 찾을 수 없습니다)** — CLI가 `PATH`에 있어야 합니다.
Operon은 `PATH`에 더해 `/opt/homebrew/bin`, `/usr/local/bin`, `~/.local/bin`, `~/.cargo/bin`을 찾습니다.
그 밖의 위치(예: `nvm` 아래)에 설치한 CLI는 Finder에서 실행한 앱에서 보이지 않을 수 있습니다. 그 명령이
동작하는 셸에서 Operon을 실행하거나(`open -a Operon` 또는 `cargo run --release`), CLI를 `~/.local/bin`에
심볼릭 링크하세요. 그런 다음 **도구 다시 확인**을 누릅니다.

**중복 실행 잠금** — 데이터 폴더를 사용할 수 있는 Operon은 하나뿐입니다. 두 번째를 실행하면
**Operon이 이미 열려 있습니다**가 표시되므로 다른 쪽을 닫고 다시 시도하세요. 설치된 빌드와
`cargo run` 빌드도 마찬가지입니다. **Operon이 로컬 데이터를 열지 못했습니다**가 나오면 데이터 폴더의 권한과
여유 공간을 확인하세요.

**상태가 "실행 중"에서 바뀌지 않거나 "대기 중"으로 남음** — 해당 CLI의 hook이 **훅 설치됨**인지 확인하세요.
**훅 실패**이면 마우스를 올려 이유를 볼 수 있습니다. hook이 없으면 Operon은 화면 판독으로 전환합니다.

**세션이 "종료"로 표시되고 마우스를 올리면 "ターミナルが残っておらず、結果を確認できません"(터미널이 남아 있지 않아
결과를 확인할 수 없음)이라고 나옴** — `tmux` 세션이 Operon 밖에서 사라져서 결과를 확인할 수 없습니다
(Operon은 이를 "실패"가 아니라 "결과 불명"으로 기록합니다). **다시 시도** 또는 **会話 ID から再開**(대화 ID로 재개)을
사용하세요.

**`tmux`에는 있지만 Operon에는 없는 세션** — **설정 → 데이터와 복구 → tmux をスキャン**(tmux 스캔)이 목록을
보여 주고, **セッションを引き継ぐ**(세션 인계)로 등록된 프로젝트에 연결할 수 있습니다.

**실제 터미널에서 접속하기** — 세션은 기본 `tmux` 서버에 있습니다. `tmux ls` 후
`tmux attach -t operon-xxxxxxxx`로 접속하세요.

**keybindings 파일이 무시됨** — 알림에 문제(잘못된 JSON, 알 수 없는 동작, 키 중복)가 표시됩니다.
고치거나 파일을 삭제해 기본값으로 되돌리세요.

## 11. 삭제와 데이터 제거

1. **먼저 hook 스위치를 끄세요**(**설정 → 에이전트**). 각 CLI의 설정 파일에서 Operon이 추가한 항목이
   제거됩니다. 등록한 계정 폴더의 항목도 없애려면 계정도 삭제하세요.
2. 세션을 중지한 뒤 Operon을 종료하세요. 세션은 일반 `tmux` 세션이므로 계속 실행 중인 것은 중지할 때까지
   계속됩니다(`tmux kill-session -t operon-xxxxxxxx`).
3. 앱을 삭제합니다. `Operon.app`(`/Applications` 또는 이 저장소의 `dist/` 등)을 휴지통으로 옮기세요.
4. Operon의 데이터를 삭제하려면 `~/Library/Application Support/com.local.operon/`을 휴지통으로 옮기세요.
   프로젝트 목록, 세션 기록, 메모, 복원 아카이브가 사라집니다. Claude Code, Codex, Antigravity가 쓴
   transcript는 각 도구의 것이므로 건드리지 않습니다.

Operon 안에서 프로젝트나 세션을 삭제해도 파일, branch, worktree는 삭제되지 않습니다.
