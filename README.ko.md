---

Operon은 Rust로 작성된 네이티브 macOS 데스크톱 앱입니다. Codex CLI, Claude Code,
Antigravity CLI(`agy`), 그 밖의 커스텀 에이전트 같은 AI 코딩 에이전트를
모든 프로젝트에 걸쳐 한 곳에서 실행하고 감독할 수 있습니다. 각 에이전트는
독립된 `tmux` 세션 안에서 동작하므로, 작업은 앱이 종료된 뒤에도 살아 있고,
실제 터미널에서 attach할 수 있으며, 언제나 사용자의 통제 아래 있습니다.

모든 것이 로컬에서 동작합니다. Operon에는 텔레메트리도, 계정도,
클라우드 서비스도 없습니다. 화면은 한국어·영어·일본어를 지원합니다.

## 기능

### 에이전트 세션

- 프로젝트와 세션 활동을 한눈에 보여 주는 홈 대시보드(최근 세션은 한 줄씩, 프로젝트마다
  시작 버튼)와, 제목·요청·에이전트·브랜치·
  프로젝트 이름 어디로든 세션을, 이름이나 경로로 프로젝트를 찾는 `⌘K`. 위아래 키로
  고르고 `Enter`로 엽니다. 기존의 자주 쓰는 작업도 그대로 맨 앞에 있습니다.
- "+"와 검색은 툴바에 하나씩. **새 세션**(`⌘N`)은 어느 화면에서든 세션을 시작하고,
  **검색·작업**(`⌘K`)이 유일한 검색입니다. 사이드바의 **기록**에서 로컬 기록 검색과
  세션 그리드를 엽니다.
- 답변을 기다리는 세션은 세션 목록에서 프로젝트보다 위에 "대응 필요"로 오래 기다린 순서대로
  고정되고, 기다린 시간과 AI가 마지막으로 한 말이 함께 표시됩니다. `⌘J`로 다음 대응 필요
  세션을 열어 그 터미널에 바로 입력할 수 있고, 기다리는 세션이 있는 동안은 툴바의
  **대응 필요 N**으로도 같은 일을 합니다. `⌘K`는 AI의 마지막 말로도 세션을 찾고, 일치도가
  같으면 대응 필요 세션을 먼저 보여 줍니다. 사이드 패널(파일·대화·변경)은 터미널 오른쪽에
  열리며 `⌥⌘B`로 접고 펼칩니다.
- **새 세션**은 지금 보고 있는 화면 위에 시트를 엽니다. 에이전트·요청·작업 위치 세 가지만
  묻고 나머지는 "상세 설정"에 접어 둡니다. 실행 버튼은 시트 오른쪽 아래에 있고 `⌘↩`로도
  누를 수 있습니다. 프로젝트의 **개요** 탭은 세션 수·커밋되지 않은 변경·worktree를 요약하고,
  이전 CLI 대화의 검색과 복원은 **기록**에 있습니다.
- 키보드는 파일입니다. 창이 반응하는 단축키(팔레트, 새 세션, 세 화면, 설정, 폴더 피커,
  터미널 안 찾기, 다음 대응 필요 세션, 사이드 패널)는 모두 id와 키를 가지며, 로컬 인덱스와 같은 폴더의
  `keybindings.json`에서 바꿉니다. `⌘K`에는 각 동작과 현재 키가 나열됩니다. 그
  목록의 "키 할당 파일 열기"는 파일이 없으면 현재 키로 만들어 위치를 열며, 이미
  있는 파일을 덮어쓰지 않습니다. 키 표기는 `Mod+Shift+K`이고 `Mod`는 ⌘입니다.
  `null`은 키 없음을 뜻합니다. 하나의 키를 두 동작에 준 파일은 어느 둘인지
  이름을 대며 통째로 거부됩니다. 절반만 적용된 키맵은 어디까지 적용됐는지 알 수
  없어서 아무것도 적용되지 않은 것보다 나쁘기 때문입니다.

- 표준 Finder 폴더 피커(`⌘O`)나 Finder에서 끌어다 놓기로 프로젝트를 추가.
  워크스페이스를 스캔해 Git 저장소를 한 번에 가져올 수도 있습니다.
  프로젝트는 임의의 로컬 작업 디렉터리이며, Git 체크아웃이라면 Git 전용
  화면도 그대로 사용할 수 있습니다.
- Codex, Claude Code, Antigravity CLI(`agy`), 커스텀 에이전트를 격리된 tmux
  세션에서 실행하거나, 빈 tmux 세션만 만들어 직접 작업에 쓸 수 있습니다.
- 실행마다 모델, 권한/샌드박스 모드, 추론 노력량을 설정합니다. 각 CLI가 실제로
  받아들이는 명령줄을 조합해 시작 전에 보여 주고, 잘못된 조합은 방금 열린
  터미널 안에서 실패하는 대신 그 자리에서 거부합니다.
- 순서가 필요한 작업은 앞선 세션 뒤에 큐잉합니다. 큐를 취소하거나,
  선행 세션이 실패한 뒤 명시적으로 시작할 수도 있습니다.
- 실패한 관리 세션은 오래된 터미널을 안전하게 점검·정리한 뒤 재시도합니다.
  기록을 삭제하는 일은 없습니다.

### 감독

- 앱을 떠나지 않고 살아 있는 에이전트 세션을 검사하고 메시지를 보냅니다.
- 다른 세션을 읽는 동안 턴이 끝났거나 질문에서 멈춘 세션은 열 때까지 목록에 표시가
  남습니다. 홈 화면 상단 배너는 항상 표시되며 기다리는 세션이 없으면 그렇다고 알려 줍니다.
  배너에 나오는 숫자는 답을 기다리는 세션, 전제가 실패해 멈춘
  세션, 읽지 않은 세션을 중복 없이 센 "당신을 기다리는 수"이며, 거기서 그 상태만으로
  좁힌 세션 목록으로 바로 이동할 수 있습니다. 행 메뉴에서 다시 읽지
  않음으로 표시하면 나중에 돌아올 수 있습니다. 표시는 실행 중에만 유지되며 재시작하면
  사라집니다.
- 세션 사이드바를 지금 손댈 수 있는 것만으로 좁힐 수 있습니다. 머리글에 놓인
  **대응 필요**·**실행 중**·**대기 중**·**종료** 네 개의 토글은 각각 현재 개수를 표시하며,
  켜면 해당 상태의 세션만 남고 해당하는 세션이 없는 프로젝트는 머리글째 사라집니다.
  여러 개를 동시에 켤 수 있고 몇 개를 숨기고 있는지는 목록 끝에 표시됩니다. 시작할
  때는 항상 아무것도 선택되어 있지 않으므로, 이유를 알 수 없는 필터가 재시작을 넘어
  남는 일은 없습니다.
- 지원하는 에이전트 CLI에는 해당 CLI의 설정 파일에 작은 상태 훅을 등록합니다.
  작업 중, 입력 대기, 완료를 화면 판독이 아니라 CLI 자신이 보고하므로 약 1초 만에
  반영되고, 실행 중인 도구 이름도 함께 보이며, 재개나 `/clear`가 완료로 오인되지
  않습니다. 등록은 설정의 스위치 하나이며 기존 항목은 그대로 두고, 끄면 추가한
  항목만 제거합니다.
- 관리 중인 터미널의 화면 자체를 읽어 여전히 작업 중인 세션과 질문에 답을
  기다리는 세션을 구분해 각 카드 옆에 표시하고, 답을 기다리는 세션 수도
  함께 보여 줍니다.
- 앱 안에서 수천 줄의 터미널 출력을 스크롤백하고, 색상 코드 없는 버퍼 전체를
  클릭 한 번으로 복사합니다. 원본 tmux 세션이나 프로젝트 폴더도 한 번의
  클릭으로 엽니다.
- 세션 목록 제목을 더블클릭해 그 자리에서 이름을 바꿉니다. 복원·재개·일반
  터미널에는 출처를 알려 주는 배지가 붙습니다.
- 에이전트가 턴을 끝내거나, 답이 필요한 프롬프트에서 멈추거나, 종료할 때
  macOS 알림을 받을 수 있습니다(선택).
- 로컬 인덱스를 잃어버려도 실행 중인 tmux 세션을 복구할 수 있습니다.
- 세션 메타데이터는 로컬에 기록되며 프로젝트 전체에서 검색됩니다.

### Git, diff, 파일

- 프로젝트별 작업 트리 변경 사항, 커밋 이력, 저장소 파일, 스킬, instruction
  파일을 확인하고, `gh`를 통해 리뷰 요약과 CI 검사를 포함해 열린 GitHub PR을
  나열합니다.
- diff는 에디터가 그리는 방식 그대로 표현됩니다: 접을 수 있는 파일 단위 분할,
  양쪽 행 번호, 각 행의 역할에 따른 색칠. 에이전트가 행을 제자리에서 고쳐 쓴
  경우에는 실제로 바뀐 낱말만 행 안에서 표시하므로, 80칸짜리 행에서 인수 하나가
  달라진 것도 읽어 대조하지 않고 눈으로 찾을 수 있습니다. 추적되지 않는 파일,
  이름 바꾸기, 첫 커밋이 없는 저장소도 포함됩니다.
- 병렬 세션을 위해 격리된 Git 워크트리를 만들고 선택합니다. 깨끗하고
  비활성인 워크트리만 앱 내 확인 후 삭제할 수 있습니다. 새 워크트리는 프로젝트
  폴더가 마침 체크아웃해 둔 커밋이 아니라 저장소의 본류(`origin/HEAD`가 가리키는
  것, 없으면 `origin/main`·`origin/master`·`main`·`master`)에서 시작하며, 어느
  것을 기준으로 삼았는지 완료 메시지가 알려 줍니다. 이미 쓰이고 있는 이름을 요청하면
  거부하는 대신 다음 번호를 붙이므로, 같은 작업을 한 번 더 병렬로 돌리는 조작은 한 번
  돌리는 조작과 똑같습니다.
- 저장소는 `.operon/setup.sh`를 넣어 두는 것만으로 새 체크아웃을 준비하는
  방법을 한 번만 선언할 수 있습니다. 워크트리를 만든 뒤 Operon이 그 스크립트의
  앞부분을 보여 주고 확인을 받습니다. 실행하면 전용 세션에서 돌아가므로 다른
  세션과 똑같이 지켜보고, 스크롤하고, 멈출 수 있습니다. 체크를 켜면 같은 내용은
  다음부터 묻지 않고 실행되고, 한 글자라도 바뀌면 다시 묻습니다. 승인한 것은
  파일 이름이 아니라 스크립트의 내용이기 때문입니다.
- 디프에 남긴 메모를 한 번에 돌려주기. 읽다가 변경된 행을 클릭해 무엇이
  잘못되었는지 적으면, 메모는 그 행 아래에 남고 앱을 닫아도 사라지지 않습니다.
  한 번의 동작으로 그 프로젝트의 메모 전부가 어느 파일 몇 번째 행인지를 짚는
  한 통의 메시지가 되어, 거기서 돌고 있는 에이전트에게 전달됩니다. 에이전트가
  응답 중이면 보내지 않습니다. 도중에 끼어들면 프롬프트가 반으로 잘리기
  때문입니다. 적었을 때와 행의 내용이 달라진 메모는 다른 행으로 옮기지 않고
  달라졌다는 사실을 그대로 전합니다.
- 읽고 있던 화면에서 그대로 일을 끝냅니다. 변경에 넣을 파일을 체크로 고르고
  (에이전트가 부탁하지 않은 파일을 건드렸다면 뺄 수 있습니다), 메시지를 쓰거나
  로컬 에이전트 CLI에게 스테이지된 디프로부터 초안을 쓰게 한 뒤 push 합니다.
  초안은 입력란에 들어갈 뿐 그대로 커밋이 되지는 않습니다. 리모트가 앞서 있으면
  push를 거부합니다. force push는 Operon에 어떤 철자로도 없습니다 — 그 문자열이
  소스에 나타나지 못하도록 테스트가 막고 있습니다.
- 워크트리를 셋 돌리면 dev 서버도 셋이 뜨고 포트는 시작 순서대로 배정됩니다.
  각 세션 헤더에 그 세션의 워크트리가 listen 중인 것만 표시합니다(`:5173 vite`,
  `:3001 node`). `lsof`로 읽고 프로세스의 작업 디렉터리로 워크트리에 연결하며,
  그 디렉터리를 포함하는 **가장 깊은** 워크트리의 것으로 봅니다. 클릭하면 열리고
  오른쪽 클릭하면 URL이 복사됩니다. 아무것도 listen 하지 않는 워크트리는 아무
  말도 하지 않습니다.
- `⌘F`로 세션의 스크롤백을 검색합니다. 찾은 곳은 그 자리에 표시되고(열은 터미널
  셀 수로 세므로 한국어·일본어 행에서도 글자 위에 얹힙니다), Enter로 차례로
  넘기면 화면이 따라갑니다. 검색 중에 입력한 글자는 에이전트에 전달되지 않으며,
  IME로 조합 중인 동안에는 확정될 때까지 검색하지 않습니다.
- Claude 사용 한도를 얼마나 썼는지 툴바에 표시합니다. Operon이 직접 요청을 보내지는
  않습니다. Claude Code는 매 턴 자신의 상태 표시줄 명령에 `rate_limits`를 넘기고
  있고(이미 받은 응답에 얹혀 옵니다), Operon은 그 자리에 읽기 스크립트를 넣습니다 —
  이미 쓰고 있는 설정은 절대 덮어쓰지 않고, 한 번 비운 자리는 다시 채우지 않습니다.
  숫자는 상태 훅과 같은 로컬 소켓으로 도착합니다. 80%를 넘으면 그 숫자만 경고색이
  되고, 30분보다 오래된 값은 흐려지며 언제 읽은 값인지 덧붙입니다.
- 파일을 체크해 커밋하면 git 인덱스가 다시 쓰입니다. 한 번 비운 뒤 체크된 것만 다시
  넣으므로, 손으로 스테이지했다가 체크를 푼 파일이 섞여 들어가지 않습니다. "AI에게
  쓰게 하기"도 CLI를 부르기 전에 같은 일을 합니다. 다만 hunk 단위 선택만은 건드리지
  않습니다. 터미널에서 `git add -p`로 파일의 일부만 스테이지해 두었다면 두 동작 모두
  파일 이름을 대며 거부합니다. 그 선택은 인덱스 안에만 있고, 잃으면 되돌릴 방법이
  없기 때문입니다.
- **worktree를 main에 병합 (Land)**: 완료된 worktree 브랜치를 로컬 메인라인에 한 번의 클릭으로
  안전하게 병합(`git merge --no-ff`)합니다. 커밋되지 않은 변경 사항이 있거나, 앞선 커밋이 0개이거나,
  에이전트가 실행 중일 때는 안전하게 거부합니다. 병합 성공 후 worktree와 브랜치의 자동 정리(`git branch -d`)도
  선택할 수 있습니다.
- **실행 스크립트 (`.operon/run.sh`)**: 프로젝트에 개발 서버나 빌드를 위한 스크립트가 있다면,
  Operon 툴바에 "실행" 버튼이 나타납니다. 미리보기와 다이제스트를 확인하고 승인하면 독립된 tmux
  세션에서 안전하게 실행됩니다.
- **풀 리퀘스트(PR) 생성 & GitHub Issue 연동**: `gh` CLI를 사용하여 diff 화면이나 세션 메뉴에서
  직접 PR을 생성할 수 있습니다(AI를 통한 요약 초안 생성 지원). 새 세션을 시작할 때는 미해결
  GitHub Issue 목록을 조회하여 세션 요청과 브랜치 이름을 자동으로 채울 수 있습니다.
- **체크포인트 & 롤백**: 턴 전송 시점이나 수동 조작으로 worktree 스냅샷(`refs/operon/checkpoints/`)을
  자동 기록합니다. 에이전트가 원치 않는 변경을 만든 경우 이전 체크포인트와의 diff 확인 및 원클릭 복원(롤백)이 가능합니다.
- **외부 에디터 실행**: worktree 목록이나 세션 메뉴에서 VS Code, Cursor, Zed, Finder를 즉시 실행하여
  작업 폴더를 열 수 있습니다.
- **프롬프트 템플릿**: 자주 쓰는 작업 요청(diff 리뷰, CI 오류 수정, 병합 충돌 해결, 테스트 작성 등)과
  프로젝트 고유의 템플릿(`.operon/prompts/*.md`)을 프롬프트 입력창에 원클릭으로 삽입할 수 있습니다.
- 스택 트레이스의 경로가 곧 파일로 가는 길이 됩니다. 터미널 안에서 가리키면 밑줄이
  생기고, 클릭하면 에디터가 그 행을 엽니다. dev 서버가 출력하는 주소도 같은 방식으로
  브라우저에서 열립니다. 밑줄이 생기는 것은 그 세션의 폴더 안에 실제로 있는
  파일뿐이라, 밑줄이 있는데 열리지 않는 일이 없고 바깥을 가리키는 트레이스가 내용을
  읽는 수단이 되지도 않습니다. worktree에서 도는 세션에서도 마찬가지로 그 worktree의
  파일로 열리며, 탭에 어느 브랜치의 것인지가 나옵니다. 같은 경로의 두 사본이 하나로
  보이는 일은 없습니다. 터미널에 포커스가 있을 때의 보통 클릭은 지금까지처럼
  포커스만 가져가고, 여는 것은 ⌥를 누른 채입니다. 대화 중인 에이전트가 마침 포인터
  아래로 흘러온 것 때문에 키보드를 빼앗기지 않도록 하기 위해서입니다.
- 내장 에디터: 접히는 프로젝트 트리(에이전트가 건드린 파일마다 Git 배지),
  탭, 행 번호, 일반적인 소스·스크립트·마크업·데이터·설정 형식의 구문 강조,
  `⌘S` 저장. Markdown은 소스가 아니라 Markdown으로 렌더링되며, 체크리스트는
  체크박스로, 언어가 붙은 코드 펜스는 구문 강조로 그려집니다. 각 파일은
  마지막 커밋과의 diff를 클릭 한 번으로 확인할 수 있습니다.
- 에이전트의 작업 위에 덮어쓰지 않습니다: 연 뒤 디스크에서 변경된 파일은
  저장을 거부하고 그 이유를 알려 줍니다.
- 에이전트의 작업을 놓치지도 않습니다: 열린 파일은 2초마다 디스크와 대조됩니다.
  저장하지 않은 편집이 없으면 그대로 다시 읽어 들이고 그 사실을 알려 주며,
  저장하지 않은 편집이 있으면 대신 고르지 않고 "다시 읽기"와 "차이 보기"를
  제시하는 바를 띄웁니다.

### CLI를 넘나드는 대화 복원

- 발견되었거나 관리 중인 Codex / Claude Code / Antigravity 세션을 프로바이더
  고유의 resume 식별자로 관리 tmux 터미널에서 다시 열어, 대화 이력을 온전히
  유지합니다.
- 같은 CLI의 구독 두 개를, 어느 쪽도 로그아웃하지 않고 나눠 씁니다. 계정이란
  Codex나 Claude Code가 로그인 정보를 두는 폴더이며, 한 번 등록해 두면 세션을
  시작할 때 에이전트 옆에서 고르는 것만으로 그 세션이 해당 계정으로 동작합니다.
  관리 훅은 이 컴퓨터의 폴더뿐 아니라 등록한 모든 폴더에 들어가므로, 다른 계정의
  세션에서도 상태 표시·읽지 않음·사용량이 그대로 동작합니다. 폴더 안을 읽지
  않으며, 그 정보가 이 컴퓨터 밖으로 나가지도 않습니다.
- 권한 모드·추론 깊이·해당 CLI가 받아들이는 스위치를 시작 화면에서 그 CLI 자신의
  목록에서 고릅니다. Operon이 자체 플래그를 쓰는 일은 없습니다. CLI가 함께 받지
  않는 스위치는 동시에 켤 수 없고, 모드와 같이 쓸 수 없는 스위치는 모드를 고른
  동안 나오지 않습니다. 그 CLI의 목록이 "확인 없이 작업한다"고 지목한 스위치에는
  표시가 붙고, 옆의 경고에 서면으로 동의하기 전에는 시작할 수 없습니다. 시작
  명령에 손으로 적은 경우도 같으며, 피커가 아니라 실제로 실행될 명령을 읽어
  판단합니다. 목록에 없더라도 이름 자체가 권한 우회를 밝히는 인자는 똑같이 확인을
  요구하므로, CLI가 내일 추가하는 플래그도 오늘부터 막힙니다. 목록이 이미 판단한
  플래그는 안전이든 위험이든 목록의 답이 우선합니다.
- 재개는 기본값이 아니라 그 대화를 하고 있던 에이전트를 그대로 다시 엽니다.
  터미널을 시작할 때의 모델·모드·스위치가 함께 따라오며, 재개와 모순되는 것만
  빠집니다. 버튼의 호버에는 무엇이 이어지는지가 나열되고, 그중 하나가 처음에
  확인을 요구했던 선택이었다면 버튼이 위험 색을 띱니다.
- Claude Code, Codex CLI, Antigravity의 어떤 대화든 셋 중 어디로든 복원할 수
  있습니다 — 나머지 둘 중 하나로도, 같은 CLI로도(첫 대화를 남긴 채 복제하는
  포크) 가능합니다.
- 복원은 CLI가 이미 로컬에 저장한 대화 기록 파일에서 규칙 기반으로 턴을
  추출합니다. 모델이 동작하지 않고, 토큰이 소모되지 않으며, 무엇도 요약되거나
  바꾸어 적히지 않습니다. 원본 바이트는 로컬 아카이브에 그대로 보관되고,
  읽기 좋은 형태가 `restored-conversation.md`로 함께 기록됩니다.
- 복원만은 기다릴 가치가 있는 긴 작업이므로 원본 대화 ID, 목적지, 경과 시간을
  알려 주는 모달 윈도우를 가지며, 언제든 백그라운드로 보낼 수 있습니다.
- 로컬 이력 검색은 최근 Codex / Claude JSONL 대화(생성된 제목 포함)를
  대상으로 하고, 앱 밖에서 실행된 프로젝트 범위의 Claude 세션도 발견합니다.
  모두 로컬에서 읽을 뿐, 아무것도 업로드하지 않습니다.

### 약속을 지키는 UI

- 다크(기본), 라이트, 고대비(다크) 세 가지 테마가 함께 제공되며 설정에서 실시간으로
  전환됩니다(열려 있는 터미널 색상 포함). 모든 색은 의미 역할에서 선택되고,
  각 테마는 그 역할을 자신의 표면에 맞게 섞으며, 자동 테스트가 모든 잉크/표면
  조합을 크기에 맞는 WCAG 2.1 AA 명암비로 유지합니다. 터미널의 ANSI 16색도
  테마를 따릅니다. [`DESIGN.md`](DESIGN.md)가 유일한 기준입니다.
- 반복되는 동작은 [Phosphor Icons](https://phosphoricons.com)(MIT)에서 온 공통
  아이콘 어휘로 그려집니다. 폰트로 번들되므로 앱 전체가 같은 선 굵기로
  그려지고, 글리프 존재 검사가 있어 조용히 빈 네모가 되는 일이 없습니다.
- 앱 내 인터페이스는 일본어·영어·한국어를 지원합니다(첫 실행 시 감지, 설정에서 변경 가능).
  아직 번역되지 않은 문구는 일본어로 표시됩니다.

### 안전장치

- 로컬 세션 인덱스를 사용할 수 있는 것은 동시에 하나의 Operon 프로세스뿐입니다.
  두 번째 실행은 경고하고 종료해 last-writer-wins 데이터 손실 위험을 피합니다.
- 메타데이터 저장소는 스키마 버전을 갖습니다. 갱신은 임시 파일 → flush → 원자적
  rename → 디렉터리 flush로 이루어지고, 이 빌드보다 새 저장소는 덮어쓰지 않고
  보존되며, 구형 인덱스는 첫 실행 때 원자적으로 편입되어 롤백 스냅숏이 됩니다.
- 실행 중 세션 정지는 tmux를 건드리기 전에 영구 저장된 취소 기록을 먼저
  쓰므로, 중단된 정지는 재시도 가능 상태로 남고 재시작 후 올바르게
  조정(reconcile)됩니다.
- 에이전트 명령은 셸과 같은 방식으로 `PATH`에서 해석되며 실행 프로브로 판정하지
  않습니다. 첫 줄에서 실패한 명령도 읽힙니다: 페인이 보존되므로 실패란
  종료 상태를 뜻하고, 앱 밖에서 세션이 사라졌다면 失敗가 아니라 結果不明으로
  기록됩니다.
- 스캔에는 상한이 있고 그 사실이 정직하게 보고됩니다: 에디터 트리는 상한이 있으며
  (`.git`, `node_modules`, `target`, `.next`는 제외), 128 KiB를 넘는 파일은 읽기
  전용으로 열리고, diff 캡처는 공유 예산을 다 쓰면 잘렸음을 알리고, 대화 기록
  검색은 후보 수·바이트·행에 상한이 있습니다. 매우 큰 저장소 전체를 보려면
  외부 에디터를 사용하세요.

## 요구 사항

| 요구 사항 | 비고 |
| --- | --- |
| macOS | Apple Silicon / Intel |
| Rust 툴체인 | `cargo`가 없다면 [rustup](https://rustup.rs/)으로 설치 |
| tmux | 세션 실행에 필수 |
| agent CLI 하나 이상 | `codex`, `claude`, `agy`가 `PATH`에 있어야 함. 커스텀 에이전트도 가능 |
| gh (선택) | GitHub PR 화면용 |

Finder에서 실행될 때는 흔한 Homebrew·local-bin 위치도 확인하므로 해당 도구들을
계속 찾을 수 있습니다.

## 시작하기

```sh
git clone https://github.com/buddypia/operon.git
cd operon
cargo run --release
```

첫 실행 화면이 tmux와 agent CLI 준비 상태를 보여 주고, 없으면 설정 안내로
안내합니다. 소스 빌드를 실행하기 전에 설치된 앱을 종료하세요(반대도 마찬가지).
단일 인스턴스 잠금이 세션 인덱스를 지킵니다.

### macOS .app 패키징

```sh
bash scripts/package-macos.sh
```

스크립트는 현재 Mac 아키텍처용으로 잠긴 의존성 집합을 빌드하고, 새 번들을
검증한 뒤 macOS의 원자적 번들 교체로 `dist/<App>.app`를 바꿉니다. 평범한
실패에서는 이전 번들이 복원되고, 최근의 정상 빌드는 수동 롤백용으로 남습니다.
번들은 로컬 개발용 ad-hoc 서명입니다. 다른 Mac 배포에는 Apple Developer ID
인증서와 notarization이 필요하며, 그 전에는 Gatekeeper의 명시적 승인이
요구될 수 있습니다.

## 개인정보

Operon 자체는 텔레메트리, 계정, 클라우드 서비스를 전혀 사용하지 않습니다.
코딩 에이전트는 별개의 도구로 실행되며 설정된 프로바이더에게 프로젝트 내용을
보낼 수 있습니다. 실행 전에 각 에이전트의 권한과 샌드박스 모드를 확인하세요.
로컬 공유 세션 아카이브에는 원본 대화 기록이 담기며 민감한 프롬프트, 도구 출력,
코드가 포함될 수 있습니다. Operon은 해당 디렉터리를 `0700`, 스냅숏을 `0600`으로
만들기 때문에 만든 계정 외에는 읽을 수 없습니다.
