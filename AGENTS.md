# Operon

- `.claude/skills/feature-pilot/SKILL.md` is the entry point: when a request adds, changes, or fixes behaviour past a one-line fix, or resumes a change under `docs/sdlc/changes/` (its `state.yaml` first), read it and follow it. A typo or a one-line fix skips it.
- When feature-pilot reaches the intent, spec, or plan, or a change somebody else started is resumed, read `.claude/skills/sdlc/SKILL.md`: route, risk, `state.yaml`, gates.
- When a test, a build, or a gate fails for a reason not yet named, or the same fix was already tried once, read `.claude/skills/root-cause/SKILL.md` before changing code.
- When a change touches the local store, the cancellation path, tmux stop or retry, store migration, or a scan or output byte limit, read `.claude/skills/durability-invariants/SKILL.md` first.
- When a landed change touches `src/` beyond `src/tests.rs`, `Cargo.toml`, or `Cargo.lock`, `/Applications/Operon.app` is stale: read `.claude/skills/ship/SKILL.md` and follow it from the main checkout.
- When a pull request looks like the next step, it is not: `.claude/skills/create-pr/SKILL.md` does not run here.
- Never commit on `main`. Work in a worktree (`make wt.new BR=feature/<task>`) and commit from that directory (`.claude/hooks/gate-commit.sh` refuses `git -C` aimed elsewhere). Push the branch, merge on `main` with `git merge --no-ff --no-edit` once CI passes (`.claude/hooks/gate-merge.sh`), `git push origin main`, and clean up from `main` via `node .claude/scripts/create-pr/ops.mjs cleanup-worktree --worktree <path>`.
- `git commit` runs `cargo fmt --check` and `cargo clippy --locked -- -D warnings` and refuses lost tests or new `#[ignore]`; `cargo test --locked` runs in CI on push, so locally run only named tests, and `cargo test --locked -- --ignored` (six tests that need a live agent CLI) when restore or the shared-session archive moved, or say that you could not. `REVIEW.md` is the review policy.
- Stopping is a state: record `awaiting-user`, `blocked`, or `failed`; at the attempt ceiling write `handoff.md` from `docs/sdlc/templates/handoff.md`.
- Ask a person only for a decision that would be unrecoverable if wrong. Anything a revert, re-run, or review undoes, decide, record in `state.yaml`, and do. Never hand a person a command to type: a recoverable step a guard refuses is a gap in the guard, and the fix goes there (sdlc 084).
- Write to a person in their words: what happens, when, and whether they must act — never this repository's review vocabulary (nit, carry, digest, round). Unfixed findings reach them through the `person:` line in `review.yaml` (sdlc 085).
- A mistake made twice becomes a check, and a new rule goes in this order: a skill, with its When-line here; a script for a deterministic step; a subagent for a large input with a small answer; a hook or a test in `src/tests.rs` for a rule prose did not hold, named in `docs/sdlc/lessons.md`; this file last, paid for by a cut.
