# Operon

- Work that adds user-visible behaviour, touches more than one module, changes a persisted shape, adds a dependency, or alters a policy runs through the pipeline in `docs/sdlc/README.md`, which produces `intent.md`, `spec.md`, and `plan.md`; a typo or a one-line fix does not. `docs/sdlc/routes.yaml` says which stages are mandatory for the kind of request and how many failed attempts it gets; `docs/sdlc/risk.yaml` says how much may be done without asking; `bash scripts/check-readiness.sh <change-dir>` gates stage 3.
- If the work already has a directory under `docs/sdlc/changes/`, read its `state.yaml` before the prose: route, stage, what is spent, and one line on what to do next.
- Stopping is a state. Record `awaiting-user`, `blocked`, or `failed`; on reaching the attempt ceiling write `handoff.md` from `docs/sdlc/templates/handoff.md` rather than trying another variation.
- Ask a person only for a decision that would be unrecoverable if it turned out wrong. Anything a revert, a re-run, or another review undoes, decide, record in `state.yaml`, and do. Never hand a person a command to type: a recoverable step a guard refuses is a gap in the guard, and the fix goes there (sdlc 084).
- Write to a person in their words: what happens, when, and whether they must act — never this repository's review vocabulary (nit, carry, digest, round). A finding left unfixed reaches them through its `person:` line in `review.yaml`, not the reviewer's (sdlc 085).
- `git commit` runs the three gates through `.claude/hooks/gate-commit.sh` and refuses a commit that lost a test or gained an `#[ignore]`. `REVIEW.md` is the review policy; `docs/sdlc/lessons.md` is where a mistake made twice is written down.
- A commit on `main` is refused by `.cli/hooks/commit-guard.mjs`. Work lands from a worktree — `make wt.new BR=feature/<task>` — committed by a session whose project directory is that tree, because `.claude/hooks/gate-commit.sh` refuses a `git -C` aimed elsewhere: this directory's cargo gates would be vouching for another checkout's code. `main` takes it with `git merge --no-ff --no-edit`, and the same session then removes the worktree and its branch with `node .claude/scripts/create-pr/ops.mjs cleanup-worktree --worktree <path>` from the main checkout — no other session may, so one left behind stays. `.cli/hooks/destructive-git-guard.mjs` refuses `reset --hard`, `push --force`, `clean -f`, and `stash clear`.
- `.claude/skills/create-pr/SKILL.md` arrived with those guards and does not run here: it pushes and opens a pull request; work here lands by local merge, and `origin` trails `main`. `.claude/skills/ship/SKILL.md` is the release that follows a landing, not a way to land.
- After every change, package with `bash scripts/package-macos.sh`, which writes `dist/Operon.app` and never touches `/Applications`, then atomically replace `/Applications/Operon.app` with it through `scripts/replace-macos-bundle.sh` in the form `.claude/skills/ship/SKILL.md` gives; move obsolete backup and `dist` bundles to Trash unless a rollback copy is requested.
- `scripts/package-macos.sh` runs `cargo fmt --check`, `cargo test --locked`, and `cargo clippy --locked -- -D warnings` over the tree before it builds, and stops on the first failure.
- Those gates skip six `#[ignore]`d tests that need a live agent CLI and are the only end-to-end coverage of the cross-CLI restore; run `cargo test --locked -- --ignored` when a change touches restore or the shared-session archive, or state that you could not.
- Build the distributable bundle with `bash scripts/package-macos.sh`; do not hand-edit its contents.
- Quit the running app before manually verifying a new installed build, so the verification uses the new executable and retains the single-instance data lock.
- Develop or modify features through `.claude/skills/feature-pilot/SKILL.md`, from any agent CLI.
